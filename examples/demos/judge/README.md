# Judge Demo

Standalone FR judge agent that evaluates feature requests against the
YAMLGraph Scripture and produces structured verdicts.

FR-450 promoted this from a demo with facade tools to a real judge with
task-shaped tools, test execution, and genuine evidence coverage.

## Usage

```bash
# Validate the graph
yamlgraph graph lint examples/demos/judge/graph.yaml

# Run the judge against a feature request
./examples/demos/judge/demo.sh feature-requests/FR-451-agent-temperature-zero-bug.md

# Or run directly
yamlgraph graph run examples/demos/judge/graph.yaml \
  --var fr_path="feature-requests/FR-451-agent-temperature-zero-bug.md" --json
```

## What It Does

1. Takes `fr_path` as input (path to a feature request)
2. Reads the FR, searches architecture for referenced REQ/CAP IDs
3. Checks git history for prior attempts and related work
4. Runs acceptance tests if they exist
5. Evaluates against 8 criteria from the Scripture
6. Returns a structured `JudgeVerdict` with:
   - `verdict` (APPROVE / AMEND)
   - `reasoning` (explanation)
   - `criteria_results` (per-criterion pass/fail)
   - `issues` (specific items to address, empty if APPROVE)

## Tools

| Tool | Purpose |
|------|---------|
| `read_file` | Read any project file in full (no truncation) |
| `search` | `rg --glob` scoped search across any directory |
| `list_dir` | Explore project structure |
| `git_log` | Search commit history for patterns |
| `run_tests` | Execute pytest on specific test files |

## Pipeline

```
START → judge → END
```

## Key Concepts

- **`type: agent`** — LLM agent node with tool access
- **Shell tools** — `read_file`, `search`, `list_dir`, `git_log`, `run_tests`
- **Inline schema** — Structured output defined in prompt YAML
- **`prompts_relative: true`** — Prompts relative to graph file
- **`max_iterations: 12`** — Room for genuine investigation

## Multi-Model Evaluation

`eval.sh` runs the judge graph across multiple LLM providers and compares verdicts.

```bash
# Run all models
./examples/demos/judge/eval.sh feature-requests/FR-452-standalone-planner-demo.md

# Cherry-pick specific models
./examples/demos/judge/eval.sh feature-requests/FR-452.md anthropic-sonnet xai-grok deepseek

# Increase timeout (default 300s)
EVAL_TIMEOUT=600 ./examples/demos/judge/eval.sh feature-requests/FR-452.md
```

### Eval Results (FR-452, 2025-05-25)

Tested 19 models total. Binary verdict prompt (APPROVE/AMEND) eliminated
false REJECTs and structured output failures.

| Model | Verdict | Time | Criteria | Notes |
|-------|---------|------|----------|-------|
| anthropic-sonnet | AMEND | 97s | 6/8 | Deep analysis, specific issues |
| anthropic-haiku | AMEND | 45s | 7/8 | Fixed by binary prompt |
| openai-o4mini | AMEND | 24s | 7/8 | Consistent critical judge |
| deepseek | AMEND | 47s | 6/8 | Improved with binary prompt |
| xai-grok | AMEND | 19s | 6/8 | Fastest critical judge |
| google-flash | APPROVE | 42s | 8/8 | Rubber stamp |
| google-pro | APPROVE | 56s | 8/8 | Rubber stamp |
| mistral-large | APPROVE | 82s | 8/8 | Rubber stamp |
| inception-mercury | APPROVE | 52s | 8/8 | Rubber stamp |
| lmstudio-gemma4 | APPROVE | 110s | 8/8 | Consistent (3/3 runs), needs 131K ctx |

**Consistency test** (4 models, 2 runs each): 3/4 flipped verdicts on
re-run. Only Gemma 4 e4b was consistent (always APPROVE). Single-run
verdicts are stochastic — majority voting recommended for production use.

**Dropped models**: gpt-5.3-codex (crash), gpt-5.4-mini (timeouts),
Replicate models (tool failures, LiteLLM version-hash bug, rubber stamps).
