# Judge Demo

Standalone FR judge agent that evaluates feature requests against the
YAMLGraph Scripture and produces structured verdicts.

FR-450 promoted this from a demo with facade tools to a real judge with
task-shaped tools, test execution, and genuine evidence coverage.

## Usage

```bash
# Validate the graph
yamlgraph graph lint examples/demos/judge/graph.yaml

# Run the judge against a feature request
./examples/demos/judge/demo.sh feature-requests/FR-451-agent-temperature-zero-bug.md

# Or run directly
yamlgraph graph run examples/demos/judge/graph.yaml \
  --var fr_path="feature-requests/FR-451-agent-temperature-zero-bug.md" --json
```

## What It Does

1. Takes `fr_path` as input (path to a feature request)
2. Reads the FR, searches architecture for referenced REQ/CAP IDs
3. Checks git history for prior attempts and related work
4. Runs acceptance tests if they exist
5. Evaluates against 8 criteria from the Scripture
6. Returns a structured `JudgeVerdict` with:
   - `verdict` (APPROVE / AMEND / REJECT / SPLIT)
   - `reasoning` (explanation)
   - `criteria_results` (per-criterion pass/fail)
   - `issues` (specific items to address)

## Tools

| Tool | Purpose |
|------|---------|
| `read_file` | Read any project file in full (no truncation) |
| `search` | `rg --glob` scoped search across any directory |
| `list_dir` | Explore project structure |
| `git_log` | Search commit history for patterns |
| `run_tests` | Execute pytest on specific test files |

## Pipeline

```
START → judge → END
```

## Key Concepts

- **`type: agent`** — LLM agent node with tool access
- **Shell tools** — `read_file`, `search`, `list_dir`, `git_log`, `run_tests`
- **Inline schema** — Structured output defined in prompt YAML
- **`prompts_relative: true`** — Prompts relative to graph file
- **`max_iterations: 12`** — Room for genuine investigation
