## 1) Key facts and main points

### The market pattern
The dominant pattern in this space is:

- **Use cheap, fast models for the “middle layer” of web pipelines**
  - crawl / fetch pages
  - clean and normalize HTML
  - chunk content
  - classify pages
  - extract entities, metadata, and structured fields
  - create short summaries
  - generate embeddings for search / retrieval
- Then reserve **larger, more expensive models** only for:
  - ambiguous cases
  - final synthesis
  - high-value reasoning
  - user-facing responses

This is especially attractive for:
- news monitoring
- competitive intelligence
- SEO/content ops
- document ingestion
- lead enrichment
- knowledge base indexing
- research assistants
- compliance / policy monitoring

### Why Haiku-class / “fast cheap” models matter
The value proposition is:
- **low latency**
- **lower cost per item**
- **high throughput**
- good enough accuracy for repetitive, narrow tasks

In practice, many production systems now use:
- small/fast hosted LLMs
- open-source small models
- hybrid pipelines combining rules + embeddings + LLMs
- “agentic” crawlers that decide what to fetch next

### Diffusion LLMs like Mercury
Diffusion-style or “non-autoregressive” LLMs are interesting because they may offer:
- faster generation
- lower latency for short outputs
- cost advantages at scale

However, in the web-content-processing market, the most common production choices still tend to be:
- **small transformer LLMs**
- hosted “mini/fast” models
- open-source models run on vLLM / TGI / llama.cpp / Ollama

So diffusion LLMs are more of an **emerging efficiency option** than the dominant mainstream production layer.

## 3) What they charge

Because live verification wasn’t possible, below is the **pricing structure pattern**, not current exact rates:

### Common pricing models
1. **Per-token pricing**
   - Most hosted LLM APIs
   - Best for summarization, extraction, classification

2. **Per-page / per-document pricing**
   - Common in web extraction platforms
   - Useful when page size varies

3. **Per-request / per-1,000 requests**
   - Common in scraping/proxy services

4. **Enterprise quote-based pricing**
   - Common for large-scale crawling, knowledge graphs, and compliance workflows

### General cost hierarchy
From cheapest to most expensive per item:
1. rules/regex + HTML parsing
2. embeddings-only classification
3. small open-source LLMs self-hosted
4. cheap hosted LLMs (Haiku-class / Flash-class / mini-class)
5. larger reasoning models
6. human review / ops-heavy workflows

### Practical rule of thumb
For web-scale pipelines:
- **classification** is usually the cheapest LLM task
- **short extraction** is slightly more expensive
- **summarization** costs more due to output tokens
- **multi-step agentic crawling** is the most expensive if not tightly controlled

## 4) What use cases dominate

### Most common production use cases

#### 1) Page classification
Examples:
- is this page a product page, article, FAQ, job post, or company profile?
- is it relevant to a topic?
- is it duplicate / near-duplicate?

Why cheap models work:
- labels are narrow
- outputs are short
- high volume matters more than deep reasoning

#### 2) Structured extraction
Examples:
- company name
- product name
- price
- location
- publication date
- author
- contact info
- topic tags

This is one of the biggest commercial uses because it directly feeds databases and search indexes.

#### 3) Summarization
Examples:
- 1–3 sentence page summary
- bullet-point article summary
- “what changed” summaries for monitoring
- executive briefings from batches of pages

Cheap models are often sufficient if summaries are short and grounded in the source text.

#### 4) Indexing for search / RAG
Typical pipeline:
- crawl pages
- clean text
- chunk
- classify
- extract metadata
- embed
- store in search/vector index

The LLM is often used before or alongside embeddings to improve relevance and structure.

#### 5) Monitoring and alerting
Examples:
- competitor site changes
- policy changes
- price changes
- news/event monitoring
- brand mentions

Here, the model often generates:
- “what changed”
- severity
- category
- summary

#### 6) Lead enrichment / business intelligence
Examples:
- identify company type from homepage
- extract vertical, size signals, tech stack hints
- classify intent
- enrich CRM records

## 5) Recent developments

Since I could not verify 2025–2026 live sources, these are **general recent trends** rather than confirmed 2025–2026 facts:

### 1) More “small model first” architectures
Teams increasingly route most items through:
- tiny classifiers
- cheap summarizers
- structured extractors

Then only escalate difficult cases.

### 2) Better structured-output tooling
The ecosystem has moved toward:
- JSON schema outputs
- function calling / tool calling
- constrained decoding
- validation loops

This makes extraction more reliable at scale.

### 3) Hybrid pipelines are now standard
A typical modern pipeline uses:
- scraper
- HTML cleaner
- deduper
- classifier
- extractor
- summarizer
- embedding model
- index

This reduces LLM spend and improves robustness.

### 4) More open-source inference in production
Self-hosting has become more practical due to:
- better small models
- faster inference engines
- improved quantization
- cheaper GPUs / better batching

### 5) Diffusion-style LLMs are an emerging efficiency story
They are interesting for latency and generation efficiency, but the market still appears dominated by conventional transformer-based small/fast models for this use case.
