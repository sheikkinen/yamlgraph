## 2026-04-20: Chaplain — Pipeline Inlining: Design Sound, Three Bugs Found

FR-259 proposes a fast-path for micro-fix PRs, routing trivial changes directly to git commit instead of full enforcement. The Plan phase comprehensively researched watch.sh routing, metrics patterns, conditional edges, and copilot nodes—establishing that all infrastructure exists. Judge validated the design as fundamentally sound: clear ROI (17.5 min/fix), strong demand (36 FRs mention micro-changes), and conservative classifier approach. However, three critical issues emerged: (1) routing order—Micro-fix check must follow the Rejected guard, not precede it; (2) PR title contradiction—documentation claims no FR-XXX in title, but code includes it; (3) state routing ambiguity—the conditional edge references `eligible` at top-level state, but it's nested under `change_spec`. All three are fixable without redesign.

**Seed:** When a copilot node outputs a complex schema (like ChangeSpec) under a single `state_key`, should individual fields be automatically promoted to top-level state variables for conditional edge evaluation, or should the schema design enforce flat state structure from the start?
