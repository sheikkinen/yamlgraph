## 2026-04-19: Chaplain — Python Nodes Variable Resolution Gap

Researched yamlgraph codebase to identify why python nodes lack variable resolution despite four other node types (llm, race, streaming, a2a) implementing it consistently. Found that `resolve_node_variables()` is called in llm_nodes.py, a2a_nodes.py, race_node.py, and streaming.py, but absent from python_tool.py. The E007 linter already validates `variables:` across all node types, creating an inconsistency. Drafted FR-252 proposing a surgical fix: adding ~7 lines to `create_python_node()` using the identical `{**state, **resolved}` merge pattern from a2a_nodes.py. Judge verified all claims against code, confirmed no conflicts, and approved for implementation. Single responsibility, minimal scope, zero breaking changes.

**Seed:** If variable resolution becomes a cross-cutting concern across all node types, should it be extracted into a shared node wrapper or middleware layer rather than duplicated in each node factory?
