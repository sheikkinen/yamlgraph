# 2026-07-17 — The questioner arc closes: canon, methods, and the judge that shouldn't be a hook

**Context:** the arc that began with "what artifact carries the
questioner" ends with mechanism design: the interrogative canon in
Scripture (eight scarred questions with firing moments), the
generative-methods layer (the fixed set — five-whys, IFR, pre-mortem,
inversion — half of it already sitting as unconsumed example graphs),
the skills gap analysis (one reception failure, one genuine hole,
both patched with field-incident citations), and the human's closing
design question: hooks can fire yamlgraphs with smaller models — the
process is always plan-judge — **should plans get judged
automatically?**

**The answer the week's evidence forces: auto-PREP yes, auto-JUDGE
no.** The judgements were this week's highest-ROI step — six for six,
every one changed the design *by a measurement the author hadn't
taken* (the 723-file census, the traceId join, the transcript
survival check, the bundle greps). That is precisely what a
hook-fired small-model judge cannot do: its value would be rhetorical
where the real judge's value was empirical. Granting authority from
an unmeasured pass is `model_as_trusted_peer` at the doctrine's most
load-bearing gate — and the chaplain lane already provides
auto-judgement for the autonomous flow, with known-weaker verdicts,
which is exactly why hard FRs come to the interactive lane.

**But the checklist tier is mechanizable, and the canon just made it
enumerable.** A small-model triage graph fired on FR creation can do
everything that doesn't require authority: run the canon against the
draft (first-consumer line present? value-prop sentence completable?
which questions apply to this FR's shape?), draft the pre-mortem
witnesses against the proposed ACs, note blast-radius candidates. The
prior-art hook already proved the pattern (retrieval aid, never
verdict). Delivery per the week's reception law: the triage output
lands **inside the FR**, in the testimony register (`claims:`), each
item requiring disposition at judgement — the FR-738 shape. The
expensive judge (model or human) then spends attention exclusively on
what the checklist cannot reach: measurement and taste.

**The two-tier split is the week's economics applied to process:**
$0.001 of small-model checklist so that the $1 judgement (or the
scarcer human read) is undiluted. Same shape as the delegation
finding (FR-744: $0.03 graph vs $4 inline) — route each cognitive
tier to its cheapest sufficient substrate, and never let the cheap
tier *sign*.

**Also closed this round:** IFR gets a template slot, not a graph
(the author holds the context; template slots have a 4-for-4 adoption
record this week) — pre-mortem gets the graph (adversary benefits
from cold eyes; the challenge gate is its proof) but triggered at
judgement-complete, not filing (needs frozen scope to attack). Both
FR-shaped, deferred to filing on request.

**Distilled:** `authority_is_not_a_checklist` — mechanize the
enumerable tier of judgement freely, but the signature requires
measurement, and measurement requires an agent that can be surprised.
A judge that cannot run a census can only approve the plan's
self-description; that is ratification, not judgement.

**Seed:** the triage graph, once real, produces a labeled dataset —
which canon questions fired per FR, which triage claims the full
judgement upheld or overturned. That's the calibration set for the
only question that matters about auto-judgement: *on which FR shapes
does the cheap tier's verdict match the expensive tier's?* Where they
match for N consecutive FRs, THAT shape can graduate to auto-judge —
promotion by measured agreement, not by throughput pressure. The
guillotine economy again: let the record decide.
