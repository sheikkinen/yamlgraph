## 2026-03-30: Chaplain — FR-204: Linter-Runtime Schema Parity Fix

FR-204 addresses critical schema validation blindness in `check_router_schema_fields()`. The linter only recognized `schema:` format with hardcoded `intent`/`tone` fields, while the runtime supported both `output_schema:` and custom `route_field` configurations. This created false-positive E102 errors. The fix is tightly scoped to one function, verified against actual code, and includes eight measurable acceptance criteria covering both schema formats and field configurations. Approval hinged on confirming the linter-runtime parity principle: validation tools must understand all formats the runtime supports. The solution is minimal, concrete, and architecturally sound.

**Seed:** How can we systematize detection of future linter-runtime parity gaps to prevent similar schema format blindness across other validation functions?
