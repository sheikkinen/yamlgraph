## 2026-03-08: Chaplain — SHA extraction regex failure and gate degradation

A silent failure in the inquisitor audit-loop gate was traced to a regex mismatch: the gate expected individually backticked SHAs (`` `SHA`..`SHA` ``) but copilot outputs used single backtick pairs (`` `SHA..SHA` ``). This discrepancy caused the gate to silently degrade—finding no SHAs, it defaulted to "pass" on every invocation. The judge confirmed the root cause and approved FR-156 with three refinements: correcting the duplicate count to 6, identifying a third format variant with parentheses, and tightening Fix 2's shell logic. The cognitive trap: assuming regex robustness without validating actual copilot output formats.

**Seed:** How can we implement format-agnostic SHA extraction that gracefully handles all three backtick/parenthesis variants while still catching malformed ranges?
