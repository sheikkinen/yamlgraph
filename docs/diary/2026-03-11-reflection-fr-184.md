## 2026-03-11: FR-184 — Implementation Reflection

**Context:** Automated the Philosopher role — a manual, sporadic ritual for detecting recurring diary heuristics — into a 5-node graph pipeline (`scan → analyze → propose → reflect → write_diary`). The `scan_diary_markers()` tool extracts `**Trap:**`, `**Heuristic:**`, and `**Seed:**` markers from diary files within a configurable lookback window. Patterns appearing ≥ 3 times across distinct files produce graduation proposals written to `.chaplain/inbox/`, where the Chaplain's Plan → Judge → Enforce pipeline picks them up. The Philosopher never edits Scripture directly — it proposes; the Chaplain decides.

**Trap:** `plausible_wrong_answer` — The original FR design placed Scripture deduplication inside the LLM `analyze` node: instruct the model to compare extracted patterns against existing `traps:` and `cures:` keys in `.github/copilot-instructions.md`. This had two compounding failures. First, the graph never passed Scripture content to the node — the Judgement annotation caught this variable gap. Second, and more insidious: even if the variable were wired correctly, LLM-based exact matching against structured YAML keys is non-deterministic. An LLM could silently judge `downstream_fix` as "not present" when the Scripture spells it `downstream_fix:` with a colon, or vice versa. A plausible wrong answer — "no duplicates found" — would pass without raising, producing spurious graduation proposals that waste the Chaplain's time. The silent fallback is harder to catch than a crash.

**Heuristic:** When the task is exact matching against a known structured vocabulary (YAML keys, enum values, ID registries), never delegate to an LLM. Parse deterministically at the Python boundary. The `_load_scripture_keys()` function reads Scripture once, extracts trap/cure identifiers with a simple regex, and `write_proposals()` filters against the resulting set — O(1) lookup, zero hallucination risk. Reserve LLM nodes for tasks that genuinely require fuzzy reasoning (the `analyze` node's pattern synthesis) and keep deterministic gates in Python tools. This is `the_one_law` applied: normalize at the boundary where external data enters, not downstream where it manifests as a missed deduplication.

**Seed:** The Philosopher currently scans for exact marker syntax (`**Trap:**`, `**Heuristic:**`, `**Seed:**`). But diary entries written before the marker convention was established — or entries that express the same heuristic in prose without the bold marker — are invisible to the scanner. Could a two-pass architecture work: deterministic regex for structured markers (fast, precise), then an LLM pass over unmarked entries to surface *implicit* patterns that were never formally tagged? This would catch the graduation candidates that predate the convention — the dark matter of the diary.
