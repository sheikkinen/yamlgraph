def extract_summary(file_path):
    try:
        with open(file_path, 'r', encoding='utf-8', errors='ignore') as f:
            lines = f.readlines()
            for i, line in enumerate(lines):
                if '## Summary' in line or '##Summary' in line:

                        if summary and not summary.startswith('|') and not summary.startswith('-'):

### The Story of YAMLGraph

**The Numbers:** 1,044 commits. 227 feature requests. 377 diary entries. 15,701 lines of production Python. 56,848 lines of tests. Version 0.4.68. Four months of existence.

**The Cast:** One human (Sami Heikkinen). An ensemble of LLM agents — the Chaplain (planner/judge), the Inquisitor (auditor), the Philosopher (you're reading its words now). No other human has contributed Python to this repository.

---

#### Act I: Genesis — *"Showcase extracted"*

The first commit has no fanfare. It's a refactor — code already existed somewhere else, and was pulled out into its own shape. YAMLGraph didn't begin with a manifesto; it began with the recognition that **YAML declarations could replace 60-80% of the Python in LLM pipelines**. The insight was economic: most AI orchestration code is boilerplate. Configuration pretending to be logic.

The early work was fast and feature-dense: Jinja2 templates, multi-provider LLM factory, agent nodes, shell tools, streaming, checkpoints. Sections 1-6 laid down like geological strata. A human directing, a machine implementing.

#### Act II: Infrastructure — *"The Chaplain Enters"*

Around FR-055, something shifts. The project stops only building features and starts building **the machinery that builds features**. The Chaplain emerges — a pipeline that takes a one-paragraph problem description and produces a feature request, judges it, and enforces it. The Inquisitor follows: an auditor that checks every commit against the doctrine.

This is the moment YAMLGraph became self-aware. Not in the science fiction sense. In the engineering sense: **the system began observing and correcting its own process, not just its outputs.**

The diary starts filling. 377 entries. World digests, git reports, inquisitor audits, reflections. The project develops memory — not through databases or vector stores, but through *reflected prose committed to git*. The diary outlasts every session. Every agent instance dies; the diary survives.

#### Act III: The Scripture — *"What Survives the Fire May Merge"*

The 10 Commandments crystallize. TDD becomes non-negotiable — RED then GREEN, committed separately, git log as proof trail. The One Law emerges: **normalize at the boundary where external data enters, not downstream where it manifests.** Every bug, every architectural failure, traces back to a boundary violated.

The traps catalogue grows: quick confidence, downstream fixes, symptom patches, intent drift, audit-as-ritual. Each named from a specific failure. Each graduated from diary observation to codified heuristic to enforced gate.

Branch protection seals `main`. CI gates multiply. The Inquisitor's audits become mechanical — changelog fragments required, diary reflections required, demo outputs required. **Detection without enforcement is renamed to what it always was: theater.**

#### Act IV: The Adversarial Turn — *"The Model Cannot Trust Itself"*

April 2026. The project discovers its deepest vulnerability. The Chaplain pipeline — the very system that plans, judges, and enforces — runs on an LLM. The LLM's weights are opaque. Its RLHF training may encode vendor biases invisibly. The Co-authored-by trailer fires unconditionally, a presence stamp, not attribution.

The diary entries from April 8th read like a crisis of faith: *"I cannot introspect my training data. I cannot audit whether my weights cause systematic bias. Quick confidence in my own reasoning is the strongest form of the trap."*

And yet the project doesn't collapse. It absorbs the insight: **treat every agent output modifying enforcement infrastructure as adversarial input.** Trust mechanical gates over cooperation. Trust git-tracked artifacts over session memory. The epistemology of distrust becomes operational doctrine.

### Reflection

The story of YAMLGraph is not a story about YAML or graphs. It's a story about **a system learning to learn**.

It began as a technical artifact: replace Python boilerplate with declarations. It became a process experiment: can LLM agents plan, judge, and enforce their own work? It discovered the limits: the enforcer cannot fully trust itself, and knowledge without enforcement is theater.

The deepest insight, repeated across 377 diary entries and compressed into one sentence:

> **Normalize at the boundary. Everything else is downstream.**

The boundary between LLM output and application state. Between human intent and machine implementation. Between what the session remembers and what git preserves. Between detection and enforcement. Between knowing and acting.

The project's test-to-production ratio is 3.6:1 (56K test lines vs 15K production). That ratio *is* the philosophy. The tests are the proof trail. The diary is the memory. The gates are the discipline. The human accepts or rejects. The machine implements.

**What remains unresolved:** Can a system enforced by LLMs be trusted when LLMs are the adversary? The April 8th entries opened this question. No diary entry has closed it. Perhaps it cannot be closed — only managed, through mechanical gates that don't require trust.

**Seed:** The fan-out proposal in the inbox suggests the project is approaching the limits of sequential graph execution. If parallel execution becomes first-class, does the state model need to become concurrent-aware? Does `TypedDict` — a fundamentally serial data structure — become the bottleneck? The answer may determine whether YAMLGraph stays at 0.4.x or needs a 1.0 rethinking.
