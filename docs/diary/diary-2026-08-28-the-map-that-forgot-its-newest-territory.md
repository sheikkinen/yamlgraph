# Diary — 2026-08-28 — The map that forgot its newest territory

**Arc:** FR-901 — skills layer folded into docs/development-process.md.

The operator asked whether an overview of skills/hooks/pre-commit/caps/
copilot-instructions relationships exists. It does — and it's good — but
`grep -c skill` returned 1, and that hit was incidental. The overview was
written when doctrine lived in one file; the sole-route arc (FR-767 and
the judge/review contracts) federated doctrine into skills *after* the
map was drawn, and nothing forces a map to track the territory it
describes.

**The trap:** call it *map_frozen_at_drawing*. A relationship overview is
an artifact with no gate on staleness — unlike ARCHITECTURE.md's RTM
(regenerated by hook) or the fr-board (drift-checked at commit), the
process narrative has no mechanical tie to the structures it names. The
skills layer became load-bearing (a Ring-1 hook now enforces a policy
*defined in a skill*) without the doc that explains the rings ever
mentioning it. The fix was cheap; the detection was luck — a direct
question from the operator.

**What worked:** the survey-first approach (grep counts + section reads
of all five candidate docs) made the FR's Problem section pure verified
inventory, and the judge's only substantive findings were contract
hygiene (state the graph-dispatch answer; un-contradict AC-04; name the
six skills so the AC can't be satisfied by a count). Judging a docs FR
cost the same rite as a code FR and caught a self-contradictory AC I had
written an hour after writing a *correct* one for FR-900 — AC discipline
does not transfer between FRs by momentum.

**Seed:** the fr-board drift check proves the pattern for keeping a
generated view honest at commit time. Could development-process.md's
*inventory claims* (skill list, ring memberships, gate counts) be
extracted into a tiny generated table with the same drift gate — so the
narrative stays prose but its facts can't silently rot? Which other
narrative docs carry unverified inventory claims today?
