# FR Knowledge Graph

> Generated by `scripts/extract_fr_graph.py` (FR-814)

## Overview

The FR knowledge graph extracts typed causal and associative relationships
from the feature-request corpus into a machine-queryable YAML artifact at
`reference/fr-knowledge-graph.yaml`.

## Schema (version 1)

```yaml
meta:
  schema_version: 1                    # Schema version for forward compat
  corpus_fingerprint: "sha256:..."     # Hash of sorted source file hashes
  fr_count: 684                        # Number of FR content files parsed
  edge_count: 3272                     # Total unique edges extracted
  causal_edge_count: 210               # Edges forming the DAG
  cluster_count: 65                    # Connected components in causal DAG

nodes:
  FR-XXX:
    status: enforced                   # First word of **Status:** line
    priority: high                     # First word of **Priority:** line
    type: bug                          # First word of **Type:** line
    requested: "2026-08-17"            # **Requested:** value
    cluster: cluster-N                 # Assigned cluster (if in one)

edges:
  - source: FR-XXX
    target: FR-YYY
    type: depends_on                   # Edge type (see taxonomy below)
    causal: true                       # Whether this edge forms part of the DAG
    confidence: 1.0                    # 1.0 = exact keyword, 0.7 = proximity
    section: "Problem"                 # Section where reference was found
    line: 47                           # Line number in source file
    rule: "depends_on_keyword_exact"   # Rule ID that fired

closures:
  FR-XXX: [FR-YYY, FR-ZZZ]            # Transitive causal dependencies

clusters:
  cluster-1:
    name: observability-evidence-route    # FR-816: semantic display name
    members: [FR-XXX, FR-YYY]             # Cluster member list

cross_cluster_mentions:                    # FR-817: weak ties between clusters
  count: 178
  edges:
    - {s: FR-XXX, t: FR-YYY, ln: 45}      # Compact: source, target, line

cycles:                                # Present only if cycles detected
  - chain: [FR-A, FR-B, FR-A]         # Exact cycle path
```

## Edge Taxonomy

### Causal edges (form the DAG)

| Type | Keywords | Semantics |
|------|----------|-----------|
| `depends_on` | "blocked until", "dependency", "depends on" | Hard prerequisite |
| `regression_of` | "regression", "introduced...regression" | Broke something |
| `spawned_by` | "seed origin", "parent plan" | Origin/lineage |
| `substrate` | "substrate", "built on", "consumes contracts from" | Infrastructure layer |
| `supersedes` | "supersedes", "replaces" | Replaces prior FR |

### Associative edges (metadata only)

| Type | Keywords | Semantics |
|------|----------|-----------|
| `prior_art` | ## Related, ## Prior art, `**Prior art:**` | Awareness link |
| `first_consumer_of` | "First consumer" section | Named trigger |
| `mentions` | Any unclassified FR reference | Weak link |

### Inverse detection

References containing "prerequisite for" or "depends on this" are classified
as `mentions` (inverse signal — the TARGET depends on the source, not vice versa).

## Regeneration

```bash
# Generate/update the graph
python scripts/extract_fr_graph.py

# Check if graph is current (for CI/pre-commit)
python scripts/extract_fr_graph.py --check
```

The graph is deterministic: running twice on an unchanged corpus produces
identical output. The `corpus_fingerprint` in the meta block is the SHA-256
of sorted per-file content hashes, enabling staleness detection.

## Prior-Art Hook Integration

The prior-art hook (`.github/hooks/scripts/checks/prior_art.py`) queries the
knowledge graph to boost candidates in the same cluster. When the graph is
present and parseable:

1. New FR's cluster membership is looked up
2. Cluster members get a 1.5× score boost
3. Output annotates graph-backed hits with `[graph:cluster]`

Missing graph: the hook emits a diagnostic to stderr and falls back to
noun-frequency scoring only. Stale graph: still used (best-effort) — staleness
is enforced by the separate `--check` gate, not by the hook itself.

## Validation

A committed fixture at `tests/fixtures/fr_graph_validation.yaml` contains
20+ manually labelled FR references with expected edge types. The accuracy
test (`tests/unit/test_fr_graph.py::TestValidationFixture`) verifies >85%
classification accuracy, excluding ambiguous edges.

## Known Cycles

Some FR pairs declare mutual dependencies (co-developed FRs). These are
genuine semantic cycles, not classifier errors. They are reported by the
extractor and listed in the `cycles` section of the output.
