# watcher2: branch name collision with previously merged PRs

## Problem

Watcher2 reuses branch names derived from inbox filenames (e.g., `feat/watcher2-gh-208`). When an inbox item is re-processed after its branch was already merged and deleted, git creates a fresh branch with the same name. The PR-reuse logic then finds the old PR is closed/merged and opens a **new PR** on the recycled branch name.

## Root Cause

Branch naming is deterministic based on the inbox filename with no uniqueness suffix. Combined with the missing deduplication gate (#232), this creates ghost PRs.

## Proposed Fix

Option A: Add a timestamp or short hash suffix to branch names: `feat/watcher2-gh-208-1777178439`
Option B: Before creating a worktree, check if a branch with that name was previously merged: `git branch -r --list 'origin/feat/watcher2-*' | ...`
Option C: Rely on the deduplication gate (#232) to prevent this entirely — if the FR is already done, we never reach branch creation.

Prefer Option C as the primary fix, with Option B as defense-in-depth.

## Context

- `feat/watcher2-gh-208` was used for both PR #211 (merged) and PR #231 (stale duplicate)
