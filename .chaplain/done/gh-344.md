# Deterministic guards: pre/post node assertions without LLM

Add a `guards:` field to node config enabling deterministic pre/post execution assertions. Guards are pure expression checks — no LLM cost, no hallucination risk in the guard layer.

## Problem

Current gaps in the execution pipeline:
1. `requires:` only checks key existence (is not None), cannot assert value constraints
2. `verification:` supports only 3 patterns (count_range, non_empty, contains) — cannot express `output.score >= 0.7` or `state.items | length >= 2`
3. No pre-execution value assertions — a bad file path burns a 60-minute copilot session before failing
4. Silent fallbacks (empty map inputs, router default_route) produce plausible wrong answers with no signal

## Proposed Syntax

```yaml
nodes:
  enforce:
    type: copilot
    guards:
      pre:
        - check: "state.fr_path | file_exists"
          on_fail: halt
          message: "FR file not found: {state.fr_path}"
      post:
        - check: "output.summary | length < 500"
          on_fail: warn
          message: "Summary too long"
```

## Expression Language

Restricted safe subset — NOT eval(), NOT Jinja2:
- `state.<key>`, `output`, `output.<field>` access
- Comparison: ==, !=, <, >, <=, >=, in, not in
- Logic: and, or, not
- Pipe filters: | length, | file_exists, | dir_exists, | type, | keys
- Literals: str, int, float, list, bool, None

## Actions

| on_fail | pre behavior | post behavior |
|---------|---|---|
| warn | log, continue | log, continue |
| halt | raise GuardViolation | raise GuardViolation |
| skip | skip node entirely | — (invalid) |
| retry | — (invalid) | re-execute node |

## Real Cases

1. **Enforce session**: pre-guard file_exists on fr_path prevents 60min wasted sessions
2. **Book translator**: post-guard `output | length >= 2` catches empty chapter markers
3. **Image pipeline**: pre-guard on map input prevents silent empty fan-out
4. **Five Whys**: post-guard `output.why_number == state._loop_counts.ask_why` catches iteration drift
5. **Router**: post-guard surfaces default_route fallthrough as observable warning

## Scope

- Add `guards` field to NodeConfig (graph_schema.py)
- Implement safe expression evaluator (~100 lines, AST-walking)
- Add pre/post guard evaluation in node execution flow (llm_nodes.py)
- Add GuardViolation model
- Lint warning: W024 for guards with invalid expressions (compile-time check)
- Demo: examples/demos/guards/ showing pre + post patterns
- Does NOT replace verification: or requires: — extends them
