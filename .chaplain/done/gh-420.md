# FR-414: Schema-as-State Loader Tool Type

## Problem

Schema-driven questionnaire graphs (ninchat_voice: callback_symptom, callback_appointment, callback_prescription, callback_examination, callback_other_topic, flex_navigator) all implement their own `load_schema()` / `load_and_merge()` Python functions to load YAML field definitions into graph state. The logic is identical: read YAML, parse fields list, store as dict in state. 6+ copies of ~30 lines each.

## Proposal

Add a declarative `schema_loader` tool type in yamlgraph core that loads YAML field-collection schemas into state:

```yaml
tools:
  load_fields:
    type: schema_loader
    path: schemas/symptom.yaml
    state_key: schema

  # Multi-schema merge variant:
  load_merged:
    type: schema_loader
    paths_from_state: active_topics    # reads list from state
    schema_dir: schemas/               # resolves "{topic}.yaml"
    state_key: schema
    deduplicate_by: id                 # merge strategy for shared fields
```

This replaces every hand-written `load_schema()` Python function with declarative YAML config.

## Scope

- Single-file loading (path → state)
- Multi-file merge from state-driven topic list (flex_navigator pattern)
- Field deduplication by ID (common fields like `subject_person`)
- Additive merge (only load new topics, preserve existing)

## Context

- ninchat_voice flex_navigator (NV-243) pioneered the schema-switching pattern
- 6 callback graphs + flex_navigator all duplicate schema loading logic
- Core `schema_loader.py` handles LLM output schemas (Pydantic); this is the complementary "data collection schema" concept
- See also FR-415 (detect_gaps utility)

## Existing Schema Pattern in ninchat_voice

### Schema YAML Format

Each questionnaire topic has a `schema.yaml` defining structured fields for data collection:

```yaml
name: <Finnish questionnaire name>
description: >
  <Purpose description>
version: "1.0"
language: fi

opening: >-
  <Bot's opening utterance>
farewell: >-
  <Closing utterance>

fields:
  - id: chief_complaint
    label: Pääasiallinen vaiva
    description: Mikä oire tai vaiva on syynä yhteydenottoon
    required: true
    type: string
  - id: duration
    label: Oireen kesto
    description: Kuinka kauan oire on kestänyt
    required: true
    type: string
```

The schema is loaded into `state.schema` and passed to LLM prompts via `variables: { schema: "{state.schema}" }`. The LLM reads field definitions to know what to extract. `opening` text is used directly via `"{state.schema.opening}"`.

### Three Identical Functions × 6 Files

Each `callback_*.py` module in /Users/sheikki/Documents/src/yamlgraph/projects/ninchat_voice/graphs contains three copy-pasted functions:

**`load_schema()`** — reads `schema.yaml` relative to the module file:
```python
SCHEMA_PATH = Path(__file__).parent / "schema.yaml"
def load_schema(state):
    schema = yaml.safe_load(SCHEMA_PATH.read_text())
    return {"schema": schema}
```

**`normalize_extracted()`** — boundary guard coercing non-dict LLM output:
```python
def normalize_extracted(state):
    extracted = state.get("extracted")
    if isinstance(extracted, dict):
        return {}
    return {"extracted": {}}
```

**`detect_gaps()`** — computes missing required fields:
```python
def detect_gaps(state):
    extracted = state.get("extracted", {})
    fields = state.get("schema", {}).get("fields", [])
    required_ids = [f["id"] for f in fields if f.get("required")]
    gaps = [fid for fid in required_ids if not extracted.get(fid)]
    return {"gaps": gaps, "has_gaps": bool(gaps)}
```

Each `graph.yaml` wires these via tools differing only in `module:` path:
```yaml
tools:
  load_schema:
    module: graphs.callback_<TOPIC>.callback_<TOPIC>
    function: load_schema
```

Note: `_common/handlers.py` already centralizes other shared functions (append_user_message, prune_messages, store_recap_summary, etc.) but these three were never lifted there.

### Flex Navigator Multi-Schema Merge

The flex_navigator differs from single-schema graphs:

- Has a `schemas/` directory with per-topic files + `_common.yaml` (6 files total)
- `SCHEMA_MAP` maps topic names → schema file paths
- **`load_and_merge()`** replaces `load_schema()`:
  - Takes `state.active_topics` (e.g. `["symptom", "appointment"]`)
  - Loads only schemas not yet loaded (additive)
  - Merges all fields into one list, tagging each with `"topic": <name>`
  - Deduplicates common fields (e.g. `subject_person`) via `_COMMON_FIELD_IDS`
- **`detect_gaps()`** is enhanced — sorts gaps by topic priority order
- **`split_results()`** reverses the merge at delivery — groups extracted fields back by topic, distributing `_common` fields to all active topics
