# feat: generate reference/module-map.md for static codebase context (Tier 2)

## Problem

Every LLM agent session starts at zero — the agent sees the codebase for the first time, every time. Currently the enforce agent spends 3-5 tool calls (grep, read_file, list_dir) just orienting itself before doing productive work. This burns tokens, adds latency, and produces non-deterministic starting conditions.

The codebase has ~630 lines of static context (CLAUDE.md + copilot-instructions.md) that tells agents HOW to behave, but nothing that tells them WHERE things are structurally.

## Proposal

Generate a `reference/module-map.md` from the codebase using `ast.parse()` and add it as an `@import` in CLAUDE.md. This provides a static "Tier 2" context layer — a machine-readable index of modules, their exports, dependencies, and test mappings.

## Acceptance Criteria

- [ ] `scripts/generate_module_map.py` script that:
  - Parses all `.py` files under `yamlgraph/` with `ast.parse()` (stdlib only, no tree-sitter)
  - Extracts: module path, line count, exported functions/classes with signatures, import dependencies
  - Generates a structured markdown file showing the module tree with key exports
  - Includes a `test_map` section mapping modules → test files
  - Runs in <2 seconds, no external dependencies
- [ ] `reference/module-map.md` generated output (~100-200 lines)
- [ ] CLAUDE.md imports the map via `@reference/module-map.md` (or equivalent reference)
- [ ] Pre-commit hook or CI step regenerates the map when `yamlgraph/**/*.py` changes (optional, can be manual initially)

## Context

Research: `docs/research/2026-05-research-context-building.md`

This is the "Minimal" variant of the Context Planner proposal — no LLM call needed, pure static generation. Later variants (Medium/Full) add a relevance classifier LLM pre-node for task-adaptive context selection.

## Token Economics

- Module map: ~450 tokens added to every session
- Expected savings: 3-5 fewer orientation tool calls per enforce session (~3000 tokens saved)
- Net: significant token savings + faster time-to-first-productive-action
