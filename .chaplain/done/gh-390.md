# fix(chaplain): validate_fix variable interpolation + sanity_check timeout

## Problem

Two issues caused gh-382 and gh-383 to fail at post-enforce stages, requiring manual PR submission.

### 1. Uninterpolated variables in validate_fix

The validate_fix state passes literal `{precommit_output}` and `{validate_gate_output}` strings — no prior state produces these context values.

Evidence: gh-382 log shows literal curly-brace strings in argv.

### 2. sanity_check timeout too short (600s)

sanity_check launches a fresh Copilot CLI session (read FR, review diff, write diary, commit). 600s is insufficient — gh-383 timed out at exactly 600s despite enforce (32 min) and validate (5 min) both passing.

enforce_session gets 3600s but post-enforce steps only get 600s.

## Fix

1. Wire precommit_output/validate_gate_output from pipeline context, or remove if unnecessary
2. Bump sanity_check timeout to 1200s

## File: `.chaplain/config/watcher-pipeline-v2.yaml`

## AC

- AC-01: validate_fix vars contain actual values or are removed
- AC-02: sanity_check timeout >= 1200s
- AC-03: Pipeline reaches submit/PR stage without timeout
