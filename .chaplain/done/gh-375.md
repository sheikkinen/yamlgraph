# feat: --json CLI output + TypeScript Node.js integration example

## Problem

There's no straightforward way to call a YAMLGraph graph from a Node.js/TypeScript backend without spinning up MCP or A2A servers.

## Proposed Solution

### 1. `--json` flag for `graph run` (~50 LOC)

```bash
yamlgraph graph run graphs/hello.yaml --json --var name=World
# stdout: {"greeting": "Hello, World!", ...}
```

Outputs the final state dict as JSON to stdout. No temp files needed. Suppresses human-readable formatting.

### 2. TypeScript example: Node backend calling YAMLGraph (~30 LOC example)

```typescript
import { execFile } from "child_process";

async function runGraph(graph: string, vars: Record<string, string>) {
  const args = ["graph", "run", graph, "--json"];
  for (const [k, v] of Object.entries(vars)) args.push("--var", `${k}=${v}`);
  const { stdout } = await execFileAsync("yamlgraph", args);
  return JSON.parse(stdout);
}
```

Minimal, no extra services, process spawn overhead negligible vs LLM latency.

### Context

- `--export-state` already dumps full JSON state to a file — `--json` is the stdout equivalent
- The `discovery.py` layer already generates JSON Schema per graph — could power typed codegen later
- ATK-päivät 2026 demo context: show clean TS integration without agent infrastructure
