# Demo-gate: validate log content, not just file presence

The demo-gate CI check (`.github/workflows/commitlint.yml`) only verifies that `demo-output.log` exists in the diff. It does not validate that the demo actually succeeded.

**Observed in FR-323:** A `demo-output.log` containing `[ERROR] yamlgraph.error_handlers: Node greet failed` passed the gate because the file was present. The demo ran with the wrong provider (Anthropic instead of Vertex) due to a missing API key, failed completely, and the error log was committed as evidence of success.

**Proposed fix:** Add a lightweight content check to the demo-gate step that fails when the log contains error indicators:
- `[ERROR]` on the final node
- Non-zero exit code recorded in the log
- Empty output (no node completed successfully)

This is `detection_without_enforcement` from the Knowledge Graph — a gate that checks shape but not semantics is advisory, not enforceable.
