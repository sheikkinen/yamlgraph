# FR-363: Per-node OTel scoping in copilot_node.py

## Summary

Add `YAMLGRAPH_OTEL_DIR` env var support to `_execute_cli` in `yamlgraph/node_factory/copilot_node.py`.

When set, each copilot node subprocess receives a per-node OTel path:
```
COPILOT_OTEL_FILE_EXPORTER_PATH=$YAMLGRAPH_OTEL_DIR/<node_name>.otel.jsonl
```

## Why

The Copilot CLI emits OTel spans automatically when `COPILOT_OTEL_FILE_EXPORTER_PATH` is in the environment (inherits from parent process). But with multi-node graphs — watcher's plan → judge → enforce — all nodes write to the same file, interleaving their spans. Per-node scoping is the minimum change to make the OTel output usable for process mining.

## Implementation

One `env=` parameter added to `subprocess.run` in `_execute_cli`:

```python
import os
otel_base = os.environ.get("YAMLGRAPH_OTEL_DIR")
node_env = None
if otel_base:
    node_otel_path = Path(otel_base) / f"{node_name}.otel.jsonl"
    node_env = {**os.environ, "COPILOT_OTEL_FILE_EXPORTER_PATH": str(node_otel_path)}

result = subprocess.run(cmd, capture_output=True, text=True, timeout=timeout, env=node_env)
```

No new dependencies. No behaviour change when unset.

## Acceptance criteria

- [ ] When `YAMLGRAPH_OTEL_DIR` is set, each copilot node writes spans to `<dir>/<node_name>.otel.jsonl`
- [ ] When unset, behaviour is unchanged (existing tests still pass)
- [ ] A watcher enforce run produces separate OTel files for each node
