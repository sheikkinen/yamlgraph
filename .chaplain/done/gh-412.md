# feat: Micro-step pipeline — extract cheap LLM/deterministic steps from validate_fix

## Problem

The `validate_fix` state uses an expensive Opus model (1200s timeout, ~$0.50/invocation) to fix problems that are mostly deterministic or solvable by cheap LLM micro-steps. Common gate failures (missing changelog fragment, bad commit title, stale branch, ruff format drift) recur predictably and don't need a full agentic session.

## Proposal

Insert cheap micro-steps between `enforce_session` and `validate_gate` to pre-solve the most common failures:

```
enforce_session → [micro_changelog_check] → [micro_title_check] → [micro_rebase] → [micro_ruff_fix] → sanity_check → validate_gate → done
```

### Extractable steps (priority order)

1. **Changelog fragment check/write** — LLM (mercury-2): read FR + diff, decide if fragment needed, generate if missing
2. **Commit title repair** — Deterministic or tiny LLM: extract FR number + scope, validate/fix conventional commit title
3. **Branch freshness** — Deterministic bash: `git fetch origin main && git rebase origin/main`
4. **Ruff auto-fix + restage** — Deterministic bash: `ruff check --fix && ruff format && git add -u`
5. **Diary reflection write** — LLM (sonnet): focused single-purpose diary generation
6. **Req-coverage marker injection** — Deterministic: parse req_coverage.py output, add missing `@pytest.mark.req` decorators

### Architecture pattern

Each micro-step follows: **cheap LLM decision → deterministic action** (or pure deterministic).

Implemented as YAMLGraph nodes in the enforce pipeline graph, running sequentially before validate_gate. Each step is idempotent — safe to skip if artifact already exists.

### Expected impact

- Eliminate ~60% of validate_fix invocations
- Reduce pipeline cost per run by ~$0.40-0.90
- Reduce pipeline wall-clock time by 5-15 minutes per iteration
- Fewer validate_gate → fix_needed loops (currently up to 5 retries)

### Acceptance criteria

- [ ] At least changelog + title micro-steps implemented
- [ ] validate_fix still serves as fallback for complex/unexpected failures
- [ ] Pipeline pass rate improves (fewer validate_gate retries)
- [ ] Each micro-step has independent timeout and error handling
