# fix(watcher): validate_fix must receive validate_gate_output diagnostics

## Problem

`validate_gate` detects diary-parity and other failures and stores structured diagnostics in `context["validate_gate_output"]`. But `validate_fix` only receives `precommit_output` — it never sees the gate diagnostics. The LLM loops 5 times seeing "all pre-commit passed" while the actual failure (e.g., missing diary in diff) is invisible to it.

## Root Cause

Three issues in the validate_fix ↔ validate_gate feedback loop:

1. **`validate_gate_output` not passed to `validate_fix`** — `.chaplain/config/watcher-pipeline-v2.yaml` validate_fix vars only include `precommit_output`, not `validate_gate_output`.

2. **`precommit_output` is literal `{precommit_output}` on first pass** — The variable doesn't exist in context before validate_gate runs, so Jinja renders the literal string.

3. **Diary-parity is a gate check, not a pre-commit check** — Pre-commit `diary-reflection-check` only checks file existence in working tree. The gate checks diff (CI-parity). The LLM only sees pre-commit output, so it never learns about the diary-in-diff gap.

## Evidence

`logs/fsm-pipeline-gh-308-20260503-234138.log`:
- validate_gate failed 5 times: `{'check': 'diary_parity', 'reason': 'missing diary reflection for FR-321 in diff'}`
- validate_fix ran 5 times, ~5-6 seconds each — too fast for meaningful work, saw no failure info
- Same pattern in gh-304/PR#311, gh-305, gh-306, gh-309/PR#313

## Proposed Fix

### 1. Pass `validate_gate_output` to validate_fix (`.chaplain/config/watcher-pipeline-v2.yaml`)
```yaml
validate_fix:
  - type: yamlgraph_async
    vars:
      validate_gate_output: "{validate_gate_output}"  # ADD THIS
```

### 2. Add `validate_gate_output` to validate graph state + prompt
- `.chaplain/graphs/watcher-enforce/validate-session.yaml`: add state field + variable
- `.chaplain/graphs/watcher-enforce/prompts/validate-session.yaml`: render gate diagnostics in prompt

### 3. Default `precommit_output` to empty on first pass
Ensure first validate_fix pass gets empty string, not literal `{precommit_output}`.

## Acceptance Criteria

- [ ] validate_fix receives `validate_gate_output` with structured failure diagnostics
- [ ] validate_fix prompt renders gate diagnostics so LLM sees diary-parity failures
- [ ] First-pass `precommit_output` defaults to empty string, not literal template
- [ ] Pipeline completes diary creation + commit without manual intervention
