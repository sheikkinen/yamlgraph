# feat: context planner pre-node with relevance classifier (Tier 2 Medium)

## Problem

The static module map (FR-331/335) gives agents a full index but no task-adaptive filtering. Every enforce session still starts with the same 206-line map regardless of whether the task touches `linter/`, `executor.py`, or `cli/`. Agents either read everything (wasteful) or skip it (back to blind exploration).

## Proposal

Add a context planner pre-node to the enforce pipeline that:

1. **Classifies** — cheap LLM call (flash/haiku) reads FR description + module map → selects ≤15 relevant source files, test files, and doc sections
2. **Assembles** — deterministic Python tool reads selected files, extracts signatures and test names, builds a context blob (~2K tokens)
3. **Persists** — writes assembled context to `docs/context/<fr-id>.md` for human review and iteration feedback
4. **Injects** — passes `assembled_context` variable to the enforce copilot prompt

## Acceptance Criteria

- [ ] `prompts/context-planner.yaml` with `ContextPlan` schema:
  - `source_files: list[str]` — paths to read
  - `test_files: list[str]` — test files to read or create
  - `doc_sections: list[str]` — reference docs relevant to task
  - `key_symbols: list[str]` — functions/classes to understand first
  - `rationale: str` — one-sentence selection strategy
- [ ] `yamlgraph/tools/context_assembler.py` (or equivalent Python tool):
  - Reads selected source files → extracts exports/signatures via `ast.parse()`
  - Reads test files → extracts `def test_*` names
  - Reads doc sections → first 50 lines
  - Budget enforcement: truncate to ≤4K tokens
  - Writes output to `docs/context/<fr-id>.md` for review
- [ ] Enforce graph wires `plan_context → assemble → enforce` as pre-nodes
- [ ] `docs/context/` directory created, gitignored=no (tracked for review)
- [ ] Existing enforce tests still pass
- [ ] Context planner uses flash/haiku model (cheap, fast)

## Context Storage (docs/context/)

Assembled contexts are persisted to `docs/context/<fr-id>.md` so that:
- Humans can review what context the agent received
- Failed runs can be diagnosed ("did it get the right files?")
- Over time, patterns emerge (which files appear most → candidates for Tier 1 promotion)
- Future Full phase can correlate context selections with success/failure outcomes

## Token Economics

| Metric | Without planner | With planner |
|--------|----------------|--------------|
| Orientation tool calls | 5-8 (grep, read, list) | 0 (pre-assembled) |
| Tokens on exploration | ~3000 | 0 |
| Context planner cost | 0 | ~700 tokens |
| Assembled context cost | 0 | ~2000 tokens |
| First productive action | ~minute 3 | ~minute 0.5 |

## Integration Point

In `.chaplain/graphs/watcher-enforce/enforce-session.yaml` (or equivalent), add:

```yaml
nodes:
  plan_context:
    type: llm
    prompt: context-planner
    model: flash
    variables:
      task_description: "{{ fr_summary }}"
      module_map_path: "reference/module-map.md"
    state_key: context_plan

  assemble_context:
    type: python
    tool: context_assembler
    variables:
      context_plan: "{{ context_plan }}"
      fr_id: "{{ fr_id }}"
    state_key: assembled_context

  enforce:
    type: copilot
    variables:
      codebase_context: "{{ assembled_context }}"
```
