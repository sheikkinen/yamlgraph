# FR-443: Document Copilot hooks in copilot-instructions.md

**Problem**: The copilot-instructions.md mentions "Pre- and Post-command hooks enforce style" but never describes:
- What `.github/hooks/` contains or how it works
- What patterns get blocked (co-author trailers, no-verify flag, multiline -m, pipe-buffer)
- How to debug a PreToolUse denial
- The lockdown/unlock mechanism
- The reasoning-pattern sentinel

An agent hitting a denial for the first time has no doctrine to reference — it retries blindly or asks the user.

**Proposed Change**: Add a ~10-line "Copilot Hooks" subsection to copilot-instructions.md under Conventions:

```markdown
### Copilot Hooks (.github/hooks/)
- **PreToolUse**: `pre-command-guard.sh` blocks co-author trailers, the no-verify flag, multiline `git commit -m`, and pytest piped without tee. On denial, read the reason and fix the command — don't retry the same pattern.
- **PostToolUse**: Modular checks (`python-checks.sh`, `yaml-checks.sh`, `markdown-checks.sh`, `fr-checks.sh`) run after file edits. Issues appear as system messages — fix before proceeding.
- **Reasoning patterns**: `reasoning-pattern-check.sh` scans for forbidden phrases. Arms a one-shot denial on next tool call.
- **Lockdown**: `.github/hooks/cmd lockdown` blocks all tools; `.github/hooks/cmd unlock` restores.
- **Audit**: All decisions logged to `.github/hooks/logs/audit.jsonl`.
- **README**: See `.github/hooks/README.md` for full hook contract and check details.
```

**Acceptance Criteria**:
- copilot-instructions.md contains a hooks section
- Section is concise (<15 lines) and references README.md for details
- Agent can self-debug a denial by reading the instructions
