# Phase 1: Agent SDK planner spike — validate backend: agent-sdk feasibility

Build a standalone Agent SDK planner script as a phase 1 feasibility spike for adding `backend: agent-sdk` to the copilot node factory.

## Context

The Chaplain's copilot nodes currently shell out to `copilot --silent -p "..."` (GitHub Copilot CLI). This works but has limitations:
- No custom tools (FR numbering collisions happen)
- No hooks (no visibility into what the agent explored)
- No structured result (parses PASS/FAIL from stdout text)
- Binary dependency (copilot CLI must be in PATH)

The Claude Agent SDK (`pip install claude-agent-sdk`) provides the same autonomous agent pattern with in-process custom tools, hooks, sessions, and no CLI dependency.

## Phase 1 Goal

A standalone `examples/agent-sdk-planner/plan.py` (~80 lines) that replicates the Chaplain's Plan step, proving three capabilities the copilot CLI cannot provide:

1. **Custom tool: `next_fr_number`** — deterministic scan of `feature-requests/` returning max+1. Prevents duplicate FR numbering (a recurring bug).
2. **Custom tool: `read_fr_template`** — always returns exact template content.
3. **Exploration audit hook** — `PostToolUse` hook that logs every file the agent reads, giving visibility into exploration breadth.

## Contract

```
Input:  topic file path (markdown with problem description)
Output: feature-requests/FR-XXX-<slug>.md written to disk
```

Same input/output contract as the current plan step. Drop-in comparable.

## Success Criteria

- [ ] Script runs with only `ANTHROPIC_API_KEY` set (no copilot CLI needed)
- [ ] `next_fr_number` tool is called and returns correct number
- [ ] FR file is written following TEMPLATE.md structure
- [ ] Hook outputs list of files explored
- [ ] Total cost per invocation < $0.15

## What This Validates (for Phase 2)

If this spike works well, Phase 2 is adding `backend: agent-sdk` to `yamlgraph/node_factory/copilot_node.py`:

```yaml
nodes:
  plan:
    type: copilot
    prompt: plan-unified
    backend: agent-sdk        # NEW — in-process, no CLI subprocess
    cli_flags:
      model: claude-sonnet-4.6
      allowed_tools: ["Read", "Glob", "Grep", "Write"]
      permission_mode: acceptEdits
    state_key: plan_result
```

Same YAML graph, same FSM orchestration, same deterministic gates between states. Just a different engine inside the copilot node.

## What This Is NOT

- Not a replacement for the Chaplain FSM (orchestration stays in bash/statemachine)
- Not a new node type (it's a backend option for the existing copilot node)
- Not a framework migration (copilot CLI backend stays for models Agent SDK doesn't support)

## Dependencies

- `pip install claude-agent-sdk` (v0.1.73+, Python 3.10+)
- `ANTHROPIC_API_KEY` environment variable

## Source

Philosopher research session (2026-05-05): Agent SDK architecture analysis + Scripture reflection on framework_costume trap. The planner spike avoids the trap by targeting a task that genuinely benefits from custom tools and hooks — not just wrapping grep in an agent.
