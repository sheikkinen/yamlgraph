# FR-441: Add files: patterns to pre-commit hooks for commit-speed optimization

**Problem**: All 23 local hooks in `.pre-commit-config.yaml` use `always_run: true`. A docs-only commit triggers vulture, jscpd, radon, import-linter, pytest — none of which can be affected by markdown changes.

**Proposed Change**: Add `files:` patterns to hooks that only matter for specific file types:

| Hook | Proposed `files:` pattern |
|------|--------------------------|
| `req-coverage-strict` | `(yamlgraph/\|tests/\|ARCHITECTURE\.md\|capabilities/)` |
| `validate-capabilities` | `capabilities/` |
| `validate-id-registry` | `(capabilities/\|scripts/validate_id_registry\.py)` |
| `noqa-confession` | `(\.py$\|docs/confessions\.md)` |
| `inline-llm-check` | `\.py$` |
| `radon-complexity` | `\.py$` |
| `file-size-gate` | `\.py$` |
| `forbid-terms` | `\.py$` |
| `jscpd-dup` | `\.py$` |
| `import-linter` | `(\.py$\|\.importlinter)` |
| `vulture-dead-code` | `(\.py$\|vulture_whitelist\.py)` |
| `hedging-check` | `\.py$` |
| `changelog-release-sync` | `(changelog/\|pyproject\.toml)` |
| `changelog-req-cross-check` | `(changelog/\|capabilities/)` |
| `diary-reflection-check` | `docs/diary/` |
| `diary-filename-check` | `docs/diary/` |
| `diary-rotate` | keep `always_run` (scheduled) |
| `pytest` | `(\.py$\|\.yaml$\|\.yml$)` |

Hooks that should stay `always_run: true`: `diary-rotate` (scheduled side-effect), `demo-proof-check` and `gitignore-boundary-guard` (cross-cutting).

**Impact**: Docs-only or diary-only commits drop from ~20 hooks to ~5. No behavioral change for Python commits.

**Acceptance Criteria**:
- Each hook has a `files:` pattern matching the file types it inspects
- `always_run: true` removed from hooks with `files:` patterns
- Full pre-commit suite still passes on Python changes
- Docs-only commit skips Python-only hooks
