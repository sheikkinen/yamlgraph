# feat(mcp): startup schema validation gate — exclude invalid tools before serving

## Feature Request: MCP Tool Schema Validation Gate

### Problem

When `yamlgraph/mcp_server.py` starts, it discovers graphs and serves them as MCP tools to Copilot without validating the generated `inputSchema`. If any tool has an invalid JSON Schema (e.g., `"type": "array"` without `"items"`), **Copilot rejects the entire MCP server** — not just the faulty tool:

```
Failed to validate tool mcp_yamlgraph_animated_character_storyboard:
Error: tool parameters array type must have items.
```

A single broken graph poisons all 100+ tools.

### Related

- #354 — root cause fix for array `items` in `_yaml_type_to_json_schema()`
- Bug: `_extract_input_vars()` only checks `state_key`, not `collect` — exposes map-node collect targets (e.g., `animated_panels`) as required input parameters

### Requirements

#### 1. Startup schema validation in MCP server

`create_server()` must validate every generated `input_schema` before registering it. Graphs with invalid schemas are **excluded** with a logged warning — not served to Copilot.

Validation rules (at minimum):
- Every property with `"type": "array"` must have `"items"`
- Every property with `"type": "object"` should have `"properties"` or `"additionalProperties"`
- `"required"` list entries must exist in `"properties"`

#### 2. Pytest coverage

Add unit tests to the test pipeline:
- `test_all_discovered_schemas_valid`: discover all default-pattern graphs and validate every `input_schema`
- `test_array_without_items_excluded`: graph with bare `{"type": "array"}` is filtered out at startup
- `test_collect_keys_excluded_from_inputs`: map-node `collect` targets are not exposed as input variables

#### 3. Fix `_extract_input_vars` collect handling

`_extract_input_vars()` currently only checks `state_key` for output detection. It must also check `collect` on map nodes. Without this, `animated_panels` (a `collect` target) appears as a required input parameter.

### Acceptance Criteria

- [ ] No graph with invalid JSON Schema is ever served via MCP `tools/list`
- [ ] Startup logs a WARNING for each excluded graph (with graph name + validation error)
- [ ] `collect` keys are treated as outputs, not inputs
- [ ] All three test cases pass in `pytest tests/unit/`
- [ ] Copilot starts successfully with all valid graphs available
