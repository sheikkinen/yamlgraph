# FR-442: Consolidate python3 calls in pre-command-guard.sh

**Problem**: `pre-command-guard.sh` calls `python3` ~7 times sequentially per invocation for JSON parsing: parse input, extract tool, extract command, extract detail, extract session_id, extract tool_use_id, plus audit log. Each is a cold interpreter start adding ~30ms, totaling ~200ms overhead per tool call.

Meanwhile, the PostToolUse check scripts use `common.sh` which consolidates parsing into a single `python3 -c` call — but `pre-command-guard.sh` predates that refactor and has its own copy of the parsing logic.

**Proposed Change**:
1. Consolidate the 6 sequential `python3 -c` parse calls in `pre-command-guard.sh` into a single call that outputs all fields (tool, command, detail, session_id, tool_use_id) as a JSON object, then extract with bash variable assignment.
2. Optionally migrate `pre-command-guard.sh` to use `common.sh` for the shared parsing/audit/emit functions, removing ~40 lines of duplicated code.

**Before** (current):
```bash
PARSED=$(echo "$INPUT" | python3 -c "...")
TOOL_NAME=$(echo "$PARSED" | python3 -c "...")
COMMAND=$(echo "$PARSED" | python3 -c "...")
DETAIL=$(echo "$PARSED" | python3 -c "...")
SESSION_ID=$(echo "$PARSED" | python3 -c "...")
TOOL_USE_ID=$(echo "$PARSED" | python3 -c "...")
```

**After** (proposed):
```bash
eval "$(echo "$INPUT" | python3 -c "
import sys, json
d = json.load(sys.stdin)
inp = d.get('tool_input', d.get('toolInput', d.get('input', {})))
cmd = inp.get('command', '') if isinstance(inp, dict) else ''
print(f'TOOL_NAME={json.dumps(d.get(\"tool_name\", d.get(\"toolName\", \"\")))}')
print(f'COMMAND={json.dumps(cmd)}')
# ...etc
")"
```

Or better: use `read` with a delimiter from a single JSON output to avoid `eval`.

**Acceptance Criteria**:
- `pre-command-guard.sh` uses at most 2 python3 invocations (parse + audit log)
- All 31 existing tests pass unchanged
- Measurable latency reduction (target: <50ms for parse phase)
