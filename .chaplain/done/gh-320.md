# Lint dead context variables in pipeline configs

## Problem

FR-321 diary seed: the validate_fix loop ran 5+ times because validate_gate stored diagnostics in context but the pipeline config never passed them to validate_fix. The variable existed but was never referenced downstream — a dead variable.

This class of bug is silent and produces plausible_wrong_answer: the LLM sees placeholder text or empty input, returns PASS in 5 seconds, and the loop repeats without progress.

## Proposed Solution

Add a lint rule (W024 or similar) that warns when a context variable is stored by one action but never referenced in any downstream action's `vars:` declarations within the same pipeline config. Analogous to W023 (unused prompt variables) but at the pipeline/FSM level.

## Acceptance Criteria

- Lint rule detects variables written to context but never read by any downstream action
- Warning emitted with variable name, writing action, and suggestion to wire it or remove it
- Existing pipeline configs pass or are fixed
- Unit tests with RED/GREEN proving detection
