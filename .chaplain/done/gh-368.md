# feat(chaplain): multi-project IDE — MVP ninchat_voice inbox routing

## Summary

Enable the Chaplain to process proposals for `projects/ninchat_voice/` — creating worktrees, running its tests, and opening PRs — without touching the yamlgraph pipeline for yamlgraph proposals.

## Problem

The Chaplain is hardcoded to govern one project (yamlgraph). Five layers of coupling block multi-project support:

1. `git worktree add` always creates yamlgraph branches
2. `.venv` symlink points to yamlgraph's environment
3. `validate_gate_action.py` runs `pytest tests/` (yamlgraph)
4. Plan graph uses yamlgraph's `ARCHITECTURE.md` and FR template
5. Inbox has one queue — no project routing

`ninchat_voice` has its own `pyproject.toml`, test suite (`pytest projects/ninchat_voice/tests/`), pre-commit config, and FR backlog. The project with the greatest governance need receives zero Chaplain automation.

## Proposed Solution — MVP (Phase 1)

Hardcode `ninchat_voice` as a second project. No generalization yet.

### Project manifest

```yaml
# projects/ninchat_voice/chaplain.yaml
project: ninchat_voice
branch_prefix: "feat/nv-"
work_dir: projects/ninchat_voice
test_cmd: "pytest projects/ninchat_voice/tests/ -q --no-cov"
precommit_config: "projects/ninchat_voice/.pre-commit-config.yaml"
fr_template: "projects/ninchat_voice/feature-requests/TEMPLATE.md"
architecture_doc: "projects/ninchat_voice/README.md"
```

### Inbox routing

```
.chaplain/inbox/
├── yamlgraph/       ← existing, unchanged
└── ninchat_voice/   ← new
```

### Changes required

| File | Change |
|------|--------|
| `.chaplain/inbox/ninchat_voice/` | New directory |
| `projects/ninchat_voice/chaplain.yaml` | New manifest file |
| `.chaplain/config/watcher-dispatcher.yaml` | Scan inbox subdirs, set PROJECT + project_config in context |
| `.chaplain/lib/watcher/worktree_setup.sh` | Read `branch_prefix` and `work_dir` from context |
| `.chaplain/actions/validate_gate_action.py` | Read `test_cmd` and `precommit_config` from context |
| `.chaplain/graphs/watcher-plan/step-plan-unified.yaml` | Pass `fr_template` and `architecture_doc` to Copilot |

## Acceptance Criteria

- [ ] Drop a `.md` proposal in `.chaplain/inbox/ninchat_voice/` — Chaplain picks it up
- [ ] Worktree created under branch `feat/nv-<topic>`
- [ ] Validate gate runs `pytest projects/ninchat_voice/tests/` (not `pytest tests/`)
- [ ] Pre-commit runs with `projects/ninchat_voice/.pre-commit-config.yaml`
- [ ] Plan phase uses `projects/ninchat_voice/README.md` as architecture context
- [ ] yamlgraph inbox (`.chaplain/inbox/yamlgraph/`) continues to work unchanged
- [ ] No hardcoded project names in dispatcher or pipeline scripts (or clearly marked TODO for Phase 2)

## Out of Scope

- Dynamic `chaplain.yaml` discovery (Phase 2 — generalize after second project proven)
- `outcaller`, `voice_runtime` manifests (Phase 3 — trivial once Phase 2 exists)
- venv isolation (Phase 4 — try shared venv first)
- scripture-dev extraction (Phase 5 — future)
