# fix: clean stale processing queue entries after successful merge

## Problem

After successful pipeline completion and PR merge, stale `.md` files remain in `.chaplain/processing/`. The FSM `done` state runs teardown but the processing file removal sometimes fails silently (race condition with dispatcher polling).

Current stale entries: `gh-337.md` (already merged as PR #338).

## Proposal

Add a post-merge cleanup step in `.chaplain/lib/watcher/post_merge.sh` that:
1. Verifies the PR is merged (via `gh pr view`)
2. Moves the processing file to `.chaplain/done/`
3. Logs the cleanup

## Acceptance Criteria

- [ ] `post_merge.sh` checks PR merge status before moving file
- [ ] Processing file moved to `done/` on confirmed merge
- [ ] Handles missing file gracefully (idempotent)
- [ ] Existing pipeline tests still pass
