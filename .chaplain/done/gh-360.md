# feat(voice): voice-driven GitHub issue creator — speak your idea, bot files the issue

## Problem

Filing GitHub issues requires stopping what you're doing, opening a browser, and typing. During development, the best ideas come mid-flow — on a walk, during a call review, right after running a test. By the time you get to GitHub, the nuance is gone.

## Idea

An intern-built voicebot that accepts inbound calls and creates GitHub issues from speech.

### Flow

1. Caller dials in (incaller server on Twilio)
2. Bot greets: "Hi! Describe your idea or issue."
3. Caller speaks freely — transcript captured via ElevenLabs STT
4. YAMLGraph conducts a short structured interview:
   - Type: feat / fix / docs / chore?
   - Scope: which area?
   - Confirm title it proposes from transcript
   - Add to chaplain pipeline? (label: chaplain)
5. Bot calls GitHub API: `gh issue create` with structured title, body, labels
6. Bot reads back the issue URL. Call ends.

### Stack

- `projects/incaller/` as starting point (inbound voice, already built)
- `voice_runtime` for TTS/STT
- YAMLGraph graph for the interview (probe-recap pattern from OC-005)
- Python tool node wrapping `gh issue create`
- Optional: chaplain label toggle — "Should this go to the chaplain pipeline?"

## Why This Is A Good Intern Project

- Uses the full stack end-to-end (voice → LLM → API)
- Immediately useful to the team — dogfooding from day one
- Self-referential: interns file issues about the voicebot *using* the voicebot
- Teaches: voice_runtime, YAMLGraph probe-recap, GitHub API, tool nodes
- Duration: 1.5–2 months

## Acceptance

- Inbound call accepted, greeting spoken
- Transcript → structured issue interview (at minimum: title + type)
- GitHub issue created with correct title, body, and optional chaplain label
- Issue URL read back to caller
- At least one real issue filed *about* the project itself via the voicebot
