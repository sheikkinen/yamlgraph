# FR-362 follow-up: close Copilot instrumentation process-mining gaps

## Summary

FR-362 produced a useful Minesweeper Copilot instrumentation POC, but the result review found gaps between the judged FR contract and the current implementation. This issue tracks the observed follow-up fixes.

## Observed gaps

1. `scripts/copilot_instrument.sh` does not pass the full instrumentation flags required by FR-362:
   - missing `--output-format json`
   - missing `--log-dir <phase>/logs`
   - missing `--log-level debug`

2. OTel content capture is not guaranteed by the runner:
   - missing `COPILOT_OTEL_EXPORTER_TYPE=file`
   - missing `OTEL_INSTRUMENTATION_GENAI_CAPTURE_MESSAGE_CONTENT=true`

3. `scripts/extract_copilot_events.py` emits only coarse event types:
   - `otel_span`
   - `git_diff`

   The POC analysis shows enough signal to extract more useful semantic events, especially from `report_intent`, tool calls, bash commands, file create/edit spans, and command failures.

4. The event schema is thinner than the judged boundary contract. Current fields are:
   - `case_id`
   - `phase`
   - `event_type`
   - `timestamp`
   - `summary`

   Judgement expected at least these additional stable fields:
   - `source`
   - `success`
   - `details`

5. Tests pass but do not cover the judged amendments:
   - required runner flags
   - OTel content capture env vars
   - expanded event schema
   - semantic event extraction
   - deterministic conformance-table output

6. The script currently captures post-phase `git-status.txt` and `git-diff.patch`, but not explicit before/after snapshots as described by the original artifact plan.

## Useful finding from the POC

The run discovered that `report_intent` spans are strong deterministic phase markers. This should become a first-class extracted event type:

```json
{"event_type": "phase_marker", "details": {"intent": "Running final verification"}}
```

## Suggested acceptance criteria

- [ ] `copilot_instrument.sh` invokes Copilot with `--output-format json`, `--log-dir`, and `--log-level debug`.
- [ ] The runner sets file-based OTel export and content capture explicitly.
- [ ] The event model includes `source`, `success`, and `details`.
- [ ] Extractor emits semantic events where observable: `phase_marker`, `test_run`, `lint_run`, `file_create`, `file_edit`, `failure`, and `retry`.
- [ ] Tests use synthetic OTel fixtures for Copilot flat-file exporter format and assert semantic event extraction.
- [ ] Tests assert required runner flags/env vars without requiring live Copilot.
- [ ] Documentation distinguishes raw spans from normalized semantic events.
