# fix(watcher): worktree_setup.sh should clean stale branches on retry

When a pipeline run fails and is re-queued, `worktree_setup.sh` fails at setup because the branch `feat/watcher2-gh-XXX` already exists (local and/or remote) from the previous run.

**Current behavior:** `git worktree add` with `--new-branch` fails if the branch exists. Pipeline immediately transitions to `failed`.

**Expected behavior:** `worktree_setup.sh` should detect an existing branch matching the topic slug and clean it up (delete local branch, remove stale worktree, optionally delete remote branch) before creating a fresh worktree.

**Impact:** Every re-queued issue hits this — requires manual `git branch -D` + `git push origin --delete` before the dispatcher can process it. See gh-304 which failed 3 times on this.

**Related:** #233 (branch name collision with previously merged PRs)
