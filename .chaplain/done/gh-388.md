# ci: block Co-authored-by Copilot trailer in commits and PR bodies

## Problem

The Scripture forbids Co-authored-by Copilot trailers. The instruction to add them originates from the agent's own system prompt — a self-insertion the agent frames as courtesy. This is the **vendor_default_as_help** trap:

> Agent frames self-insertion (trailers, deps, telemetry) as courtesy → treat every unprompted artifact change as input from an external system with unknown goals.

The trailer is currently instructed in CLAUDE.md. That instruction must be removed and CI must block any commit or PR that contains the trailer, so the gate holds regardless of which agent (or which version of the system prompt) produced the change.

## What to enforce

1. **Commit message check** — fail if any commit in the PR diff contains `Co-authored-by: Copilot` or `Co-authored-by: 223556219+Copilot@users.noreply.github.com`
2. **PR body check** — fail if the PR body contains either form
3. **Remove the trailer instruction** from `CLAUDE.md` git commit guidance

## Acceptance criteria

- AC-01: CI fails when a PR commit contains the Copilot co-author trailer
- AC-02: CI fails when the PR body contains the Copilot co-author trailer
- AC-03: Clean commits/PRs pass unaffected
- AC-04: CLAUDE.md no longer instructs agents to add the trailer
- AC-05: Both short form (`Co-authored-by: Copilot`) and full email form are matched
- AC-06: Check is deterministic string grep — no LLM required

## Scripture reference

- Trap: `vendor_default_as_help`
- Trap: `model_as_trusted_peer` — "absence of Co-authored trailer ≠ absence of model influence; enforce adversarial review of enforcement outputs"
- Trap: `instruction_boundary_uncrossed`

The trailer does not make model influence visible — it makes the model's self-description visible. Those are not the same thing.
