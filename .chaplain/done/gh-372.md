# Add pre-commit guard forbidding gitignore changes

## Problem

Add a pre-commit action that forbids changes to `.gitignore` by default.

This is a safety gate prompted by the damage report in `docs/diary/2026-05-12-private-repo-dataloss-recovery.md`. In that incident, private repositories were accidentally present inside the YAMLGraph workspace. An LLM/agent path had to bypass protection in order to commit private repositories into YAMLGraph. The resulting cleanup crossed repository boundaries, involved forceful deletion, and caused real data-loss risk: tracked files were recoverable, but untracked local-only files had no guaranteed recovery path.

The core assumption: a human maintainer knows how to bypass the protection deliberately when a `.gitignore` change is truly intended. Agents and routine automation should not be able to alter ignore boundaries casually.

## Requested change

Implement a pre-commit hook/action that fails when `.gitignore` is modified, unless an explicit human bypass path is used.

Expected behavior:

- Block staged changes to root `.gitignore`.
- Prefer blocking any `.gitignore` file in the repository, including nested paths, unless the FR/Judgement chooses a narrower root-only scope.
- Print a clear message explaining that `.gitignore` changes alter repository privacy/safety boundaries.
- Mention the diary reference: `docs/diary/2026-05-12-private-repo-dataloss-recovery.md`.
- Provide a documented human-only bypass path for intentional changes.
- Do not use `--no-verify` as the documented bypass.

## Acceptance criteria

- A test or hook-level verification demonstrates that staging `.gitignore` changes fails.
- A normal commit without `.gitignore` changes still passes.
- The failure text explains why this protection exists and points to the diary entry.
- The bypass mechanism requires explicit human intent and is documented in the FR or reference docs.
- The solution fits the existing pre-commit/Chaplain enforcement style.

## Notes

This guard is not meant to make `.gitignore` immutable. It is meant to make changes to ignore boundaries exceptional, visible, and human-owned.
