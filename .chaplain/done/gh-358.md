# feat(chaplain): PR title should use primary feat/fix commit, not final diary commit

## Problem

When watcher2 creates a PR with multiple commits (e.g., feat → format → diary), the PR title is set from the **last commit** (diary reflection). Since squash merge uses the PR title as the merge commit message, the git log on main shows `docs(diary): FR-XXX watcher2 sanity-check reflection` for changes that are actually `feat(mcp): FR-355 startup schema validation gate`.

### Evidence

PR #357 contains:
1. `feat(mcp): FR-355 add startup schema validation gate` (+92/−22 in discovery.py, +63/−3 in mcp_server.py, +178 new test file)
2. `chore(format): FR-355 validate remediation ruff formatting`
3. `docs(diary): FR-355 watcher2 sanity-check reflection`

The PR title (and therefore the squash commit on main) became the diary commit message, hiding the real feature.

## Proposed Fix

When watcher2 opens or updates the PR, set the PR title from the **first commit whose type is `feat` or `fix`** in the branch. Fall back to the first non-chore/non-docs commit if none match. The diary commit should never win title priority.

## Acceptance Criteria

- [ ] PR title reflects the primary `feat`/`fix` commit message
- [ ] Diary and formatting commits do not override the title
- [ ] Existing PRs with only docs commits still get a valid title
