- **FR-1027 Recap pull-request axis**: `examples/demos/recap/` now reports what the window *decided*, not only what it committed. One graph-local python node (`nodes/prs.py`) derives `owner/name` from `repo_path`'s `origin` remote, makes exactly one bounded `gh pr list` subprocess invocation (fixed argv, `shell=False`, 60 s timeout, 300-row cap), and buckets the result in code into **merged in window**, **closed unmerged in window**, and **open now** — membership decided against the exact epoch from `git rev-parse --since` so midnight truncation cannot move a row, ordering by decision timestamp then number descending, lines assembled as `#<number>|<created>→<end>|<N>d|<title>` with the title byte-identical to the JSON. The axis never transits the model: `prompts/recap.yaml` is unmodified, its schema stays `{workstreams, hotspots}`, and `finalize_recap` attaches the three buckets and one note the way FR-704 attaches orphans. A window with no pull requests (`available: True`, empty buckets) is a different value from an axis that could not be read (`available: False` with one of nine stable reasons — no origin, non-GitHub host, local remote, malformed URL, `gh` missing, timeout, non-zero exit with or without stderr, unparseable JSON, missing field); only four narrow exception classes are absorbed and anything else propagates. Reaching the cap says results *may* be truncated, since a 301st row is not observable. `scripts/weekly_recap.py` emits the note once before the three new sections so a cap warning survives non-empty buckets, and renders `(not collected)` rather than `(none)` for an axis that made no observation. FR-821's Monday workflow passes the existing `RECAP_PAT` as `GH_TOKEN` to the recap step only. Witnessed against this repository in `feature-requests/FR-1027.witness.md`, which carries PR #627 — closed unmerged after four judge and three review rounds, and invisible to every git-only recap.
