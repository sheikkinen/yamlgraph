- **FR-1030 Shared desktop-toast notification tool**: `examples/shared/notify_toast.py` adds `send_toast(title, message)` — the local, immediate rung that was missing between stdout (needs the terminal in front), SMTP (`FR-907`, remote and credentialed), and the phone (`call-me-maybe`, last resort). It submits a native notification through the facility each OS already provides: `osascript` on macOS, `powershell.exe` driving WinRT `ToastNotificationManager` on Windows, `notify-send` on Linux. The AppleScript and PowerShell sources are frozen constants — caller text travels as `argv` or as child environment and reaches the Windows toast XML through `CreateTextNode`, so it is never interpolated into a command string, script body, or markup; `shlex.quote()` is deliberately absent because no shell is invoked. Success is `{"submitted": True, "backend": ...}`: the OS accepted the request, **not** proof a human saw it. Unsupported platform, blank input, missing binary, non-zero exit, and timeout all raise `ToastError`; no failure path returns a `submitted`-shaped mapping. Declared via `examples/shared/send_toast.tool.yaml` (FR-768) and consumed by `examples/demos/hello`, which now announces its own greeting with `on_error: skip` so a headless or notifier-less host records a visible failure envelope and still reaches `END`. macOS delivery is visually witnessed; Windows and Linux are unit-witnessed only, and the README says so. (REQ-YG-672)
