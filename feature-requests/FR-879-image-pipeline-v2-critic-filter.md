# Feature Request: FR-879 Image Pipeline v2 — Single Model, Critic-Filtered Prompts, z-image

**Priority:** MEDIUM
**Type:** Feature
**Status:** Proposed
**Effort:** 1–2 days
**Requested:** 2026-08-24
**First consumer / first event:** the operator (sheikkinen), today: run
one command, watch 10 candidate prompts get generated by the default
`.env` provider, see the FR-876 critic score and the boundary filter
them in a visible table, and get z-image renders of only the survivors.
The demo IS the product: "the filter working" is what the consumer
asked to see.

## Summary

A new version of `examples/image_pipeline` with the opposite shape of
v1: instead of an unguarded M×N fan-out (concepts → map/subgraph →
render everything), v2 is **generate → score → filter → render** on a
single LLM provider (default from `.env`), demonstrating the FR-876
critic as a live quality gate. One LLM node generates 10 candidate
prompts in the corpus style; a scoring tool (deviant-daily's trained
critic + generation boundary) ranks them and rejects out-of-band
candidates; only the top-k survivors are rendered via Replicate
z-image. The rejection table is a first-class output artifact.

## Value Statement

The operator gets style-true images at lower Replicate cost (only
survivors render), and yamlgraph gains its missing example shape: a
deterministic local-model critic gating a frontier-LLM generator —
"LLM proposes, cheap frozen judge disposes" — instead of the
`model_as_trusted_peer` LLM-judges-LLM pattern used everywhere else.

## Problem

- `examples/image_pipeline` v1 renders every generated prompt: M×N
  images with zero quality control (`examples/image_pipeline/graph.yaml:55-88`).
  Bad prompts cost the same Replicate money as good ones.
- FR-876 built and witnessed a corpus critic (3.3 M-param char model,
  val loss 1.02, deterministic scoring in one forward pass) plus a
  generation boundary (redaction / 8-gram novelty / shape) — but no
  consumer exercises the critic role yet. Scoring is ~1000× cheaper
  than generation (one parallel forward pass vs ~900 sequential).
- v1 is also multi-provider ceremony (`run_multi_provider.sh`,
  `styles-batch.sh`); the actual daily use is one provider from `.env`.

## Ideal Result

`yamlgraph graph run examples/image_pipeline_v2/graph.yaml --var
style="dark fantasy, ink" --full` with only `.env` for configuration:
10 candidates stream from the default provider, a table prints each
candidate's per-char NLL, band verdict (too-likely / in-band /
too-unlikely), and boundary verdict, the top 3 in-band survivors render
via z-image with prompts embedded in EXIF, and the rejection table is
saved next to the images. A reader of the output directory understands,
without reading code, why each rejected prompt was rejected.

## Proposed Solution

Two deliverables across the established repo boundary (precedent:
FR-876 — deviant-daily owns model + boundary; yamlgraph orchestrates).

**D-A: `training/score.py` in `sheikkinen/deviant-daily`** (the critic
CLI, ~60–100 lines):

- Loads `training/ckpt/model.pt`; computes per-char NLL for each input
  prompt in ONE forward pass (no sampling).
- Calibration: score the 294 `val.txt` docs once, persist the reference
  distribution (`training/ckpt/calibration.json`, e.g. p10/p90 per-char
  NLL); verdict = `too_likely | in_band | too_unlikely` against it.
- Composes the existing `Boundary` check (redaction / novelty / shape)
  into the same JSON verdict per prompt.
- CLI contract: prompts as JSON lines on stdin → JSON lines out
  (`{prompt_sha, nll_per_char, band, boundary, verdict}`); stamps
  output with ckpt+corpus git SHA (`artifact_carries_code_identity`).
- Tests: calibration determinism, band edges, boundary composition,
  one-forward-pass scoring matches a hand-computed tiny case.

**D-B: `examples/image_pipeline_v2/` in yamlgraph** — authored ONLY
via the graph-authoring sole route (`scripts/author.sh`, FR-767):

```
START → generate_candidates (llm, 10 prompts, style var)
      → score_filter (python tool → subprocess to deviant-daily score.py)
      → save_report (python: rejection table + survivor list)
      → generate_images (python: Replicate z-image, survivors only, top-k var)
      → END
```

- **Single model:** provider comes from `.env` `PROVIDER` only; no
  per-node provider overrides, no multi-provider scripts.
- `score_filter` locates the critic via `DEVIANT_DAILY_DIR` env var;
  **fails fast** with an actionable message (train commands) when the
  clone/ckpt/calibration is missing — no silent skip-the-filter
  fallback (Commandment 6).
- z-image rendering reuses v1's `generate_images` node pattern (EXIF
  embedding); `top_k` var (default 3) caps Replicate spend.
- v1 stays untouched — it demos map/subgraph fan-out, a different
  lesson.

```bash
# The demo
export DEVIANT_DAILY_DIR=~/src/deviant-daily
yamlgraph graph run examples/image_pipeline_v2/graph.yaml \
  --var style="dark fantasy, baroque, chiaroscuro" \
  --var candidates="10" --var top_k="3" --full
```

## Alternatives Considered

- **LLM-as-judge for filtering:** rejected as the default — a second
  LLM judge is nondeterministic, costs tokens per run, and reproduces
  `model_as_trusted_peer`; the frozen 13 MB critic gives identical
  verdicts on every run. (An optional semantic-judge stage can be a
  later FR; style ≠ semantics is a known critic limit.)
- **Copy the scorer into yamlgraph:** rejected — duplicates boundary
  regexes and model code across repos; subprocess contract keeps one
  source of truth (`where_is_the_repo_boundary`).
- **Publish model.pt as a release asset for consumers without training:**
  deferred — viable later; the first consumer has the clone already.
- **Rework v1 in place:** rejected — v1 demos map/subgraph fan-out; two
  different lessons, two examples.
