# Research: FR-943 — Census Row-Level Failure Containment

**Date:** 2026-08-31
**Question:** When one item in a census map fan-out yields a malformed
model envelope, the whole batch aborts in `reduce_ledger` after every
LLM call has been paid for. Where and how should that failure be
contained?

## Incident record (raw output read first)

Four of six 200-item spark-full batches died on 2026-08-31; every raw
failure record was read end-to-end and is committed as
[tests/fixtures/fr943_incident_map_errors.json](../tests/fixtures/fr943_incident_map_errors.json).
Surprising details a generated dump could not produce:

- Index 178 (batch-01): the model emitted `abstain_reason: ''` but
  omitted `abstained` itself — a *partial* abstention envelope, not a
  wholesale format failure.
- Indexes 3, 131, 88: the truncated Pydantic `input_value` shows item
  content leaking into the model's own `judgement` field — shell
  fragments `*.md 2>&1`, `git push -q origin main`,
  `tail -4 | cut -c1-160`. The judged text contaminated the judgement:
  all four bad items are prompts *containing shell commands*, which
  haiku echoes instead of classifying.
- All four failures share one class (missing `abstained`); no timeout
  or provider error occurred in 1,003 calls. The incident class is
  narrow but the containment mechanism (`_error` findings) covers the
  wider class (timeouts, 529s) for free.

## Solution classes

### S-1: Reducer row-level containment (CHOSEN)

Classify per-finding anomalies in `_rows_by_index`: attributable
model-owned failures become fail-closed abstained rows (reason +
verbatim evidence preserved); structural impossibilities stay
batch-fatal. Effort: ~0.5 day. Risk: LOW — deterministic, demo-scoped,
replayable from the committed fixture. Precedent: FR-940 normalized
the model's *label* at exactly this boundary; FR-727/730
(`junk_drawer_cap`) established demote-never-drop with evidence
preserved.

### S-2: Framework map-level error-row policy (`on_branch_error: preserve`)

Teach `map_compiler` to emit a typed "failed branch" record that
consumers opt into. Rejected: the map layer *already* normalizes
branch failures into `_error` findings with `_map_index` — the
remaining question is disposition, which is consumer semantics.
Other map consumers legitimately want fail-fast; a framework knob
would need its own FR-936-style contract research (the FR-936
judgement split four map contracts for exactly this reason). Effort:
2+ days, framework surface. Risk: MEDIUM — cross-consumer contract.

### S-3: Native RetryPolicy on the judge sub-node (FR-936 D-4)

Retry transient envelope misses inside the branch. Disposition:
COMPOSES, does not substitute. Retry cuts frequency; exhausted retries
still surface as `_error` findings, which today still abort the batch.
D-4 is unauthored and its judgement (R-6) shows `wrap_for_reducer`
currently swallows the exceptions RetryPolicy would need to see —
a prerequisite renegotiation this demo fix should not wait for.

### S-4: Relax `CorpusCensusFinding` (optional fields + defaults)

Make `abstained`/`abstain_reason` optional so malformed envelopes pass
schema and reach the reducer as data. Rejected: coerces a failed
envelope into a plausible judged row (`plausible_wrong_answer` — the
row would carry a judgement contaminated by item content, as the
incident record shows); covers only the schema-miss subclass, not
timeouts/provider errors; weakens the schema boundary where the
provider's type lie is supposed to die.

### S-5: Prompt hardening ("always emit abstained: true/false")

Rejected — `two_strike_split`: this ledger boundary already had its
prompt strike (the 1,007-item run needed a hand-tightened rubric
before FR-940 mechanized it). The incident items contain shell text
that derails haiku regardless of instruction emphasis; mechanizable
levels belong in code.

### S-6: Post-hoc quarantine tooling (status quo)

`tmp/quarantine_failures.py` + batch rerun. Rejected — one wasted
O(batch) rerun per newly discovered bad item (~800 calls witnessed);
detection only happens after the spend is forfeited.

## Preserved disagreement

S-2 remains the principled long-term answer if a *second* map consumer
needs row preservation — at that point the policy graduates from
consumer code to a framework contract (same graduation rule as
Scripture heuristics). Today there is exactly one consumer; building
the knob now is `growth_as_default`. Recorded so a future FR can cite
this disposition rather than re-derive it.
