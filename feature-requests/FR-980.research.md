## Addendum: boundary corrections per FR-980 judgement R-7 (2026-09-03)

The five findings above conflated coverage claims across solution
classes. This addendum corrects the boundary of each, without re-running
the persona graph:

1. **Pre-commit hook alone** (os-infra-primitivist) — originally framed
   as covering "every allocator (direct file edit, chaplain automation,
   CI)". Corrected: a pre-commit hook fires only at commit time and
   cannot intercept an agent tool call before the write happens. It is
   one half of a combined design (FR-980 §Proposed Solution 3+4), not a
   standalone solution.
2. **Boundary-enforcement inventory** (data-process-planner) — the
   general shape was right; the four-row inventory it produced was
   incomplete (missing Chaplain Plan/Enforce as distinct executable
   paths, and wrongly listing a validator as an allocator). Corrected in
   FR-980's own inventory table (R-1).
3. **Corpus-census pattern** (yamlgraph-native-planner) — accurate as a
   characterization of what the corrected inventory *is* (a small,
   directly-verifiable census); no boundary correction needed.
4. **Subtractionist dissent** — accurate as filed; no correction needed.
5. **LedgerDB precedent** (librarian) — accurate as an external analog;
   FR-975 already implements the equivalent pattern for this repository.

**Compared boundary summary** (per judgement R-7): route-specific
protocol calls (FR-975) cover compliant callers only; child-scoped
PreToolUse grants (this FR, R-2/R-3) cover the Copilot-tool-call surface
only; local pre-commit + required CI validation (this FR, R-4) is the
only surface that reaches a direct human/operator editor bypass; OS/file-
permission denial and validation-only subtraction were considered and are
not adopted as the primary mechanism (see FR-980 §Alternatives
Considered). No single class covers every allocator; the adopted design
combines three of them deliberately.
