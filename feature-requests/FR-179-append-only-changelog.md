# Feature Request: Append-Only Changelog Fragments

**Priority:** HIGH
**Type:** Enhancement
**FR:** FR-179
**Status:** Approved
**Effort:** 2 days
**Requested:** 2026-03-09

## Summary

Replace the monolithic `CHANGELOG.md` with per-FR fragment files under `changelog/unreleased/`, aggregated by script on release. Remove `CHANGELOG.md` from git tracking entirely to eliminate the #1 merge-conflict source.

## Value Statement

All contributors avoid merge conflicts on CHANGELOG.md — the second-largest conflict source — by writing isolated fragment files that never collide, with the monolithic file generated only at release time.

## Problem

Every PR that completes enforcement appends a line to the `## [Unreleased]` section of `CHANGELOG.md` via `finalize_merge.sh`. When multiple PRs are open concurrently, they each modify adjacent lines in the same file section. This causes merge conflicts on every second merge, requiring manual resolution on a generated artifact.

The file is 87 KB with 1427 lines and growing. It is not hand-authored content — it is mechanically assembled from FR metadata. A monolithic generated file is the wrong format for concurrent append.

## Proposed Solution

### Design Decision: Remove CHANGELOG.md from Git Tracking (Option A)

The original proposal's staleness guard created the exact conflict it claimed to solve. This revision chooses **Option (a)** from the Judgement: remove `CHANGELOG.md` from git tracking entirely.

- `CHANGELOG.md` is added to `.gitignore`
- It is generated on-demand via `scripts/aggregate_changelog.py`
- It is generated and included in release artifacts during version bump
- No staleness guard is needed — an untracked file cannot conflict
- Developers who want a local copy run `python scripts/aggregate_changelog.py > CHANGELOG.md`

This is the cleanest option: zero conflict surface, zero staleness ambiguity.

### Directory Structure

```
changelog/
  unreleased/           # One file per FR, created by finalize_merge.sh
    FR-169-reflexion-loop.md
    FR-176-audit-parallelism.md
  0.4.61/               # Frozen on release
    FR-172-loop-exit-target.md
    FR-173-bugfix-pipeline.md
```

### Fragment Format

Each fragment is a minimal markdown file matching the existing CHANGELOG entry format:

```markdown
---
type: feat
scope: graph
req: REQ-YG-093
---
**FR-172 Configurable Loop Exit Target**: Add `loop_exits` graph-level config that maps node names to custom exit targets when loop limits are reached.
```

The YAML front matter enables structured aggregation (grouping by type into Added/Fixed/Removed sections). The body is the exact line that currently appears in CHANGELOG.md.

### Aggregation Script

`scripts/aggregate_changelog.py` reads all fragment files, groups by type, and emits a complete `CHANGELOG.md` to stdout:

```bash
python scripts/aggregate_changelog.py > CHANGELOG.md
```

The generated file begins with a header comment:
```markdown
<!-- Generated by scripts/aggregate_changelog.py — do not edit manually -->
```

Grouping rules:
- `type: feat` → `### Added`
- `type: fix` → `### Fixed`
- `type: removal` → `### Removed`
- Within each section, entries sorted by FR number ascending

### Migration Script

`scripts/migrate_changelog.py` performs the one-time split of existing `CHANGELOG.md` into fragment files:

1. Parse each versioned section (`## [X.Y.Z]`)
2. Extract individual entries (lines matching `- **FR-XXX ...`)
3. Write fragment files to `changelog/{version}/FR-XXX-slug.md`
4. Entries in `## [Unreleased]` go to `changelog/unreleased/`
5. Verify round-trip: aggregated output matches original (modulo whitespace)
6. Add `CHANGELOG.md` to `.gitignore`
7. Run `git rm --cached CHANGELOG.md` to untrack the file

### finalize_merge.sh Changes

Replace the current CHANGELOG.md insertion logic (lines 50–70) with fragment file creation:

```bash
# Before (current):
sed ... CHANGELOG.md

# After:
SLUG=$(echo "$FR_TITLE" | tr '[:upper:]' '[:lower:]' | tr ' ' '-' | tr -cd 'a-z0-9-')
cat > "changelog/unreleased/${FR_NUM}-${SLUG}.md" << EOF
---
type: $CHANGE_TYPE
scope: $SCOPE
req: $REQ_ID
---
$CHANGELOG_LINE
EOF
git add "changelog/unreleased/${FR_NUM}-${SLUG}.md"
```

### Gate Updates (Resolves Judgement Issue 2)

Two existing enforcement gates currently require `CHANGELOG.md` modification. Both must be updated to check for fragment files instead:

**Pre-commit hook** (`changelog-required` in `.pre-commit-config.yaml`):
```bash
# Before: checks git diff --cached --name-only for CHANGELOG.md
# After: checks git diff --cached --name-only for changelog/unreleased/*.md
entry: "bash -c 'msg=$(cat \"$1\"); if echo \"$msg\" | grep -qE \"^(feat|fix)(\\(.*\\))?:\" && ! git diff --cached --name-only | grep -qE \"^changelog/unreleased/\"; then echo \"ERROR: feat:/fix: commits must include a changelog fragment in changelog/unreleased/\"; exit 1; fi' _"
```

**CI job** (`changelog-gate` in `.github/workflows/commitlint.yml`):
```bash
# Before: checks PR diff for CHANGELOG.md
# After: checks PR diff for changelog/unreleased/*.md
if git diff --name-only "$BASE_SHA" "$HEAD_SHA" | grep -qE '^changelog/unreleased/'; then
  echo "✅ Changelog fragment found"
else
  echo "::error::feat/fix PRs must include a changelog fragment in changelog/unreleased/"
  exit 1
fi
```

### Release Workflow

On version bump:

```bash
VERSION="0.4.62"
mkdir -p "changelog/${VERSION}"
mv changelog/unreleased/*.md "changelog/${VERSION}/"
python scripts/aggregate_changelog.py > CHANGELOG.md
# CHANGELOG.md is .gitignored — include in release artifacts only
git add changelog/
git commit -m "chore(release): ${VERSION} changelog freeze"
```

## Alternatives Considered

**1. Git merge driver for CHANGELOG.md** — A custom `.gitattributes` merge driver could auto-resolve adjacent-line conflicts. Rejected: fragile, doesn't work on GitHub server-side squash merges, and still leaves a monolithic file.

**2. CI-only generation (no fragments committed)** — Generate CHANGELOG.md entirely in CI from git log / PR metadata. Rejected: loses human-readable fragment authoring, makes local `cat CHANGELOG.md` impossible without CI, and couples release to CI availability.

**3. towncrier / changie** — Established fragment-based changelog tools. Rejected: adds external dependency for a simple problem; our fragment format is three lines of YAML front matter + one markdown line. The aggregation script is ~80 lines of Python. The cost of the dependency exceeds the cost of the implementation.

**4. Keep CHANGELOG.md tracked with per-PR regeneration (Option C from Judgement)** — `finalize_merge.sh` creates fragment + regenerates CHANGELOG.md. Reduces conflict severity (re-run script vs manual resolution) but does not eliminate it. Rejected in favor of Option A which eliminates the conflict entirely.

**5. Keep CHANGELOG.md tracked, staleness guard on release only (Option B from Judgement)** — The towncrier model: CHANGELOG.md may be stale between releases. Rejected: stale tracked files confuse contributors and trigger unnecessary diffs.
