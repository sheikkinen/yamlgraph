## What is sound

The problem and first event are concrete: concurrent local test runs freeze the iMac, while a named LAN host has already completed one Copilot-mediated file-write round trip (`feature-requests/FR-948-lan-copilot-delegation.md:8`, `feature-requests/FR-948-lan-copilot-delegation.md:25-30`, `feature-requests/FR-948-lan-copilot-delegation.md:164-175`). Replacing the unimplemented SSH, WSL2, Python-matrix, key-distribution, and rsync design is materially smaller than carrying both channels (`feature-requests/FR-947-remote-pytest-delegation.md:20-54`; `feature-requests/FR-948-lan-copilot-delegation.md:177-184`). Retiring that speculative surface follows the repository's subtractionist rule (`.github/copilot-instructions.md:85`).

The proposal correctly reuses the encrypted, pinned, non-admin WinRM boundary rather than inventing a second transport, places remote output behind Pydantic models, keeps v1 stateless, and demands a real physical-host witness in addition to offline tests (`feature-requests/FR-948-lan-copilot-delegation.md:75-102`, `feature-requests/FR-948-lan-copilot-delegation.md:104-123`). Those are sound architecture and testability choices. The fixed ASCII PowerShell artifact also preserves the platform lesson already evidenced by FR-945 (`feature-requests/FR-945-lan-recon-skill.md:75-85`, `feature-requests/FR-945-lan-recon-skill.md:185-188`).

This remains one coherent concern: a repo-local operational skill that submits one isolated task over an existing transport and returns typed evidence. Retiring the design it replaces is lifecycle bookkeeping for that same concern, not a second implementation. Strategic classification: **contrib/operational skill**, not a framework primitive. It has one concrete host/channel and reuses existing skill, Copilot CLI, Pydantic, and WinRM patterns; it does not justify a generic fleet scheduler, remote-command API, or YAMLGraph node (`.github/skills/judge-fr/doctrine.md:49-57`; `feature-requests/FR-948-lan-copilot-delegation.md:8-23`).

The revised record must compare at least: WinRM plus Copilot CLI; deterministic WinRM remote command execution without an LLM; FR-947's SSH plus pytest-xdist route; a self-hosted CI runner; and CI-only/no-LAN-delegation subtraction. Preserve the strongest dissent, select one class, and give one final `is_this_a_graph` answer. For the selected v1, the answer must distinguish the remote-execution channel from any graph workload it may invoke.

Disposition every retrieval hit, including `FR-945.research.md` and `FR-899-org-repo-census-azure.judgement.md`, which appear in the retrieval block but not in FR-948's prior-art disposition (`feature-requests/FR-948.research.md:10-15`; `feature-requests/FR-948-lan-copilot-delegation.md:10-15`, `feature-requests/FR-948-lan-copilot-delegation.md:147`). Also disposition CAP-249, which one research row invokes despite being an unrelated tool-slot capability (`feature-requests/FR-948.research.md:21`; `capabilities/CAP-249-tool-slot-binding.yaml:1-20`). This is a hard research gate: a persona-shaped duplicate table is not 4-6 genuine solution classes with preserved disagreement (`.github/skills/judge-fr/doctrine.md:118-128`).

Promote a sanitized, committed Phase 2f transcript or fixture and cite it from the FR. The proposal's feasibility claims repeatedly cite `tmp/copilot-spike-phase2f.log`, but that file is not committed, while the committed brief says Python self-provisioning was still a "spike step to verify" (`feature-requests/research-briefs/copilot-cli-remote-delegation-brief.md:13-27`). The evidence must include the exact Copilot command shape, exit code, elapsed time, credit/tokens tail, resume line, redacted WinRM invocation shape, and artifact content, with no credential. Remove or qualify every claim not established by that record.

### R-2: Reconcile FR-945's actual schema and dependency contract

Make implemented FR-945 behavior a prerequisite rather than saying it has already landed. FR-945 is still `Proposed`, pins `pypsrp>=0.9,<1.0`, and its `LanHostInventory` has no `git`, `node`, npm, or Copilot fields (`feature-requests/FR-945-lan-recon-skill.md:5`, `feature-requests/FR-945-lan-recon-skill.md:52-54`, `feature-requests/FR-945-lan-recon-skill.md:87-116`; `pyproject.toml:52-54`). FR-948 instead claims `pypsrp>=0.10` and requires those nonexistent inventory fields (`feature-requests/FR-948-lan-copilot-delegation.md:50-52`, `feature-requests/FR-948-lan-copilot-delegation.md:65-67`).

Fold the existing `pypsrp>=0.9,<1.0` constraint into FR-948. Validate only fields FR-945 actually emits before connecting: resolved address, computer name, probe timestamp, `admin=False`, Remote Management Users membership, and typed inventory errors relevant to those fields. After connection, run a fixed, non-LLM preflight that emits a Pydantic `RemoteCopilotPrerequisites` object for Git, Node major at least 22, and Copilot CLI presence/version. Refuse each missing or malformed prerequisite explicitly. Do not amend FR-945's schema under FR-948 authority.

### R-3: Freeze code identity, prompt transport, skill loading, and artifact attribution

The first use is testing or analyzing the current code, but the FR defines only a caller-supplied remote clone path; it neither proves which revision is present nor isolates concurrent agents (`feature-requests/FR-948-lan-copilot-delegation.md:8`, `feature-requests/FR-948-lan-copilot-delegation.md:34`, `feature-requests/FR-948-lan-copilot-delegation.md:63-72`). That violates the repository's shared-index warning exactly when the stated consumer is concurrent agents (`.github/copilot-instructions.md:154`). Freeze v1 to clean, committed local source: record the local repository identity and HEAD SHA; require the pre-provisioned remote canonical clone to contain that SHA; create a unique detached Git worktree per run beneath `C:\Users\copilot\yamlgraph-runs\<run-id>`; and refuse a dirty local tree, absent SHA, repository-identity mismatch, unsafe run path, or worktree collision. Source upload, `git fetch`, cloning, and remote runtime installation are not part of this v1.

Resolve the prompt contradiction. `--prompt-file` is local, but `wrapper.ps1` currently expects a remote path without any transfer step (`feature-requests/FR-948-lan-copilot-delegation.md:59`, `feature-requests/FR-948-lan-copilot-delegation.md:68`). Read and validate the file on the mac, pass its UTF-8 contents as a bound PowerShell `$Prompt` parameter, and invoke Copilot with that single argument; never interpolate prompt content into the script literal.

Pass `--add-dir <run-worktree>`, not `<clone-dir>/.github/skills`. The cited help says the added directory is the root whose `.github/skills` and `.github/agents` are loaded, while AC-06 points at the nested skill directory (`feature-requests/FR-948-lan-copilot-delegation.md:152`, `feature-requests/FR-948-lan-copilot-delegation.md:173`). Require delegated outputs under one run-owned directory inside the detached worktree; after Copilot exits, the fixed wrapper copies only that directory to `\\<host>\Images\yamlgraph-delegations\<run-id>`. Enumerate that run directory, not every share file whose mtime changed during a global window (`feature-requests/FR-948-lan-copilot-delegation.md:98`). This makes concurrent artifact attribution mechanically testable.

### R-4: Put credential and tool authority before human review

Remove `--allow-all-paths`. The run worktree is the only Copilot-accessible root; the fixed wrapper, not the model, performs the SMB copy. State truthfully that a token placed in the Copilot process environment can be read by tools launched by that process. Exact-string redaction protects logs but does not prove the token cannot be transformed or exfiltrated. The current "never through the model's context" and least-privilege claims overstate what `--allow-all-tools --allow-all-paths` establishes (`feature-requests/FR-948-lan-copilot-delegation.md:19`, `feature-requests/FR-948-lan-copilot-delegation.md:34`, `feature-requests/research-briefs/copilot-cli-remote-delegation-brief.md:35-41`). Use one canonical input name, `GH_TOKEN`; do not add an ungoverned alias. Clear the process environment in a `finally` path, keep the token out of arguments/script text/files/results, and preserve exact-value redaction as defense in depth.

**Human safety question, to be answered and dated in the FR:** Does the operator authorize a non-interactive LLM process with `--allow-all-tools` and a live GitHub credential on Huutokauppakone, constrained to a disposable per-run worktree, with the credential's minimum permissions, repository access, expiry/rotation policy, and incident revocation action written in the FR? A "no" answer rejects this execution design; silence grants no authority.

Remote bootstrap and self-provisioning are not authorized in v1. The FR simultaneously says Copilot installs Python/dependencies and says remote dependencies are preconditions not installed by this FR (`feature-requests/FR-948-lan-copilot-delegation.md:19`, `feature-requests/FR-948-lan-copilot-delegation.md:50-52`). Remove the installation claim and fail loudly when a workload lacks its pre-provisioned runtime. A later host-bootstrap or controlled self-provisioning capability requires separate authority.

### R-5: Replace the fictional credit ceiling with truthful spend semantics

The wrapper cannot abort a run based on a credit value parsed only after Copilot has exited. The FR calls this both an aborting ceiling and a post-hoc refusal (`feature-requests/FR-948-lan-copilot-delegation.md:34`, `feature-requests/FR-948-lan-copilot-delegation.md:70`, `feature-requests/FR-948-lan-copilot-delegation.md:117`, `feature-requests/FR-948-lan-copilot-delegation.md:156`). Rename the v1 option to `--max-reported-credits` and define it as a post-run acceptance threshold, not a cap: the run has already spent the credits; exceeding the threshold makes the delegation CLI non-zero while preserving the typed result and artifacts. If credit parsing is absent or malformed, fail closed with an explicit policy status rather than accepting `credits_used=None`. The finite wall-clock timeout is the only pre-completion bound evidenced here.

**Human spend question, to be answered and dated in the FR:** Does the operator accept that v1 can detect reported overspend only after completion and therefore cannot guarantee a hard per-run or per-day credit cap? A "no" answer requires committed evidence of a vendor-supported pre-execution cap or a different execution design before authority.

### R-6: Make request, result, error, and test contracts executable

Add schema tables for `LanDelegationRequest`, `RemoteCopilotPrerequisites`, and the completed-run result. Define `FieldError` ownership rather than referencing an unspecified type. Separate pre-run refusal from completed execution: library preflight failures raise typed exceptions and produce no success-shaped result; a launched run records distinct Copilot exit code, delegation-policy status, timeout state, parsed-cost status, source SHA, run ID, artifact root, and errors. A Copilot failure or post-run policy violation returns a validated diagnostic result from the library but a non-zero CLI status. Remove `--resume` from the v1 interface entirely; capturing an observed resume ID for audit does not authorize continuation.

Replace the twelve-item test list with direct witnesses for every boundary introduced by R-2 through R-5: malformed or stale FR-945 inventory; relevant inventory field errors; each missing remote prerequisite; missing credential; prompt UTF-8/size handling; unsafe host, clone, run, log, and result paths; dirty local source; repository/SHA mismatch; per-run worktree collision and two-run isolation; bound prompt contents absent from script text; root-level `--add-dir`; absence of `--allow-all-paths`; token absence from arguments, script, logs, result, and artifacts on success, auth failure, timeout, and malformed output; Copilot non-zero exit; timeout; missing/malformed/exceeded credit report; malformed wrapper JSON; Pydantic failure; unique artifact attribution; and cleanup behavior. Mock DNS, filesystem clocks, Git, SMB, and WinRM so offline tests open no socket.

The live witness must execute one named representative repository workload, not only another trivial file write. Record the exact local and remote SHA, unique run ID/worktree, command, Copilot and delegation statuses, elapsed time, reported credits, and copied artifact/result paths. This is required because the feature exists to move a physical workload, and a mock or unrelated file write does not prove code identity or delegation (`.github/copilot-instructions.md:80-81`; `feature-requests/FR-948-lan-copilot-delegation.md:121-123`, `feature-requests/FR-948-lan-copilot-delegation.md:158`).

### R-7: Complete governance without widening the primitive

Add generated `ARCHITECTURE.md` requirement coverage to CAP-257/REQ-YG-636, retain the requirement tags and strict coverage command, and make AC-16's "no unauthorized surface" concrete by using the frozen list below (`feature-requests/FR-948-lan-copilot-delegation.md:125-133`, `feature-requests/FR-948-lan-copilot-delegation.md:159-162`). Update FR-947's supersession record, documentation, changelog fragments, implementation status, and diary only after the revised contract is enforced. Do not modify CAP-30 or the YAMLGraph Copilot node; it is precedent, not an implementation surface.
