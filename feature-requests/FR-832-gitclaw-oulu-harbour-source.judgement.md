## What is sound

FR-832 correctly follows FR-831's decomposition gate: it implements only Task
2, a contained Digitraffic Marine harbour source snapshot, while Hilma, KTweb,
composition, synthesis, runtime/policy changes, and final publication remain
separate tasks. This removes FR-828's source-discovery and multi-source overload.

The source contract is closed and source-specific. It freezes the public
unauthenticated Digitraffic URL, gzip, strict size/encoding/JSON boundaries,
`portCalls` structure, stable identity, future-ETA ordering, source-health
taxonomy, no raw-response retention, and cargo-inference prohibition.

The strategic classification is **contrib/example acceptance task**, not a
YAMLGraph framework primitive. The first consumer is a public GitClaw cookbook
reader observing one generated `FIOUL` source snapshot, and implementation is
confined to one generated feature directory under the existing public
read-only policy.

## Required revisions

### R-1: Put reviewed-transfer provenance inside the exact issue body

The public issue itself must link the public-safe FR-831 transfer contract,
FR-832, and this judgement. It must not require private control-plane access,
private permalinks, raw responses, chat context, or source rediscovery.

### R-2: Freeze the run-instant boundary

The feature accepts `date` and ISO-8601 UTC `run_instant`. Fixtures and fixture
smoke supply a frozen instant. Live/cron execution may default it to current UTC
only when omitted and must record it. ETA selection compares to `run_instant`,
never calendar `date`.

### R-3: Make vessel-type hints non-inferential

Without a reviewed mapping table, render exactly
`Vessel type hint: code <code> (hint only; cargo unknown)` when the code exists
and omit the line when absent. Do not permit free-text labels or inference from
vessel name, route, ports, berth, or an LLM.

selection/synthesis, final bulletin publication, workflow/runtime/policy/secret

or paths outside the generated feature plus normal ledger/provenance state.
