# Feature Request: Anthropic Prompt Caching Demo with System Segments

**Priority:** MEDIUM
**Type:** Feature
**Status:** Proposed
**Effort:** 2 days
**Requested:** 2026-04-25

## Summary

Create a practical demonstration of Anthropic prompt caching using system_segments to validate FR-276's implementation and provide a working example for graph authors.

## Value Statement

Graph authors get a concrete working example of how to leverage Anthropic prompt caching with system_segments, enabling them to optimize costs and performance in their own multi-step workflows by caching stable context.

## Problem

FR-276 implemented system_segments with cache: true support for Anthropic prompt caching, but there is no practical demonstration showing how to use this feature effectively. The existing cache demo (examples/demos/cache/) focuses on node-level result caching (FR-032), not prompt-level token caching.

Without a working demo, graph authors cannot:
- Understand how to structure prompts with cacheable segments
- See the cost/performance benefits in practice
- Learn best practices for segment design
- Validate that their cache hints are working correctly

## Proposed Solution

Create `examples/demos/prompt-caching/` with:

1. **Two-node graph** using provider: anthropic with shared cached system context
2. **Shared prompt template segments** demonstrating cache reuse across nodes
3. **Documentation** showing cache hit patterns and cost savings
4. **Working demo-output.log** proving execution with Anthropic API

### Graph Structure

```yaml
# examples/demos/prompt-caching/graph.yaml
version: "1.0"
name: prompt-caching-demo
description: Demonstrates Anthropic prompt caching with system_segments

provider: anthropic
prompts_relative: true
prompts_dir: prompts

state:
  topic: str

nodes:
  analyze:
    type: llm
    prompt: analyze
    variables:
      topic: "{state.topic}"
    state_key: analysis
    
  reflect:
    type: llm 
    prompt: reflect
    variables:
      topic: "{state.topic}"
      analysis: "{state.analysis}"
    state_key: reflection

edges:
  - from: START
    to: analyze
  - from: analyze  
    to: reflect
  - from: reflect
    to: END
```

### Prompt Templates with Shared Cache

Both `analyze.yaml` and `reflect.yaml` share identical cached system segments:

```yaml
# prompts/analyze.yaml
system_segments:
  - content: |
      You are an expert on the YAMLGraph framework. YAMLGraph is a YAML-first
      framework for building LLM pipelines using LangGraph. The key insight:
      60-80% of AI workflows can be defined entirely in YAML (graphs + prompts +
      schemas) without writing Python code.
      
      [Large stable context about framework capabilities, patterns, best practices...]
    cache: true
  - content: |
      Your task is to analyze the given topic and provide structured insights.
    cache: false

schema:
  name: Analysis
  fields:
    summary: {type: str, description: "Brief topic summary"}
    key_points: {type: list[str], description: "3-5 main points"}
    complexity: {type: str, description: "Low/Medium/High"}

user: |
  Analyze this topic: {topic}
```

```yaml
# prompts/reflect.yaml  
system_segments:
  - content: |
      You are an expert on the YAMLGraph framework. YAMLGraph is a YAML-first
      framework for building LLM pipelines using LangGraph. The key insight:
      60-80% of AI workflows can be defined entirely in YAML (graphs + prompts +
      schemas) without writing Python code.
      
      [Identical large stable context - should hit cache...]
    cache: true
  - content: |
      Your task is to reflect on the analysis and provide actionable recommendations.
    cache: false

schema:
  name: Reflection
  fields:
    strengths: {type: list[str], description: "Analysis strengths"}
    gaps: {type: list[str], description: "Missing perspectives"}
    next_steps: {type: list[str], description: "Recommended actions"}

user: |
  Based on this analysis of "{topic}":
  {analysis}
  
  Provide reflective insights and recommendations.
```

## Alternatives Considered

1. **Extend existing cache demo** - Rejected because it focuses on node-level caching (FR-032), not prompt caching. Mixing concepts would confuse users.

2. **Create watcher2-specific demo** - Rejected because it would be too complex for demonstrating the core caching concept. A simple 2-node flow is more educational.

3. **Use external prompt files** - Considered but inline prompts make the demo more self-contained and easier to understand.

4. **Mock Anthropic responses** - Rejected because the whole point is validating real API behavior with cache hits.
