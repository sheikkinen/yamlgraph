## What is sound

The FR names a real governance gap. The cited diary records that the wrappers and adapters are coherent locally but inherited, not locally witnessed: no tests cover `scripts/judge.sh`, `scripts/review.sh`, the sentinels, or artifact contracts, and no CAP/REQ/ARCHITECTURE traceability entry names the bundles (`docs/diary/diary-2026-07-24-route-contract-is-not-hook-contract.md:20-34`). The local searches agree: existing wrapper/sentinel strings are absent from `tests/` and `.github/hooks/tests/` except for an unrelated hook-test phrase, and `REQ-YG-569` / `CAP-211` are absent from `capabilities/` and `ARCHITECTURE.md`.

The proposed tests are the right shape. FR-758 scopes them to `tests/unit/test_fr758_judge_review_wrappers.py`, marks them `process`, uses a stub `YAMLGRAPH_BIN`, and avoids API keys (`feature-requests/FR-758-judge-review-traceability-reconstruction.md:74-85`). That aligns with FR-756: `process` is registered as the marker for tests coupled to `.chaplain`, examples, or scripts (`pyproject.toml:182-192`), and `tests/conftest.py` mechanically fails unmarked unit modules that reference process boundaries (`tests/conftest.py:33-39`, `tests/conftest.py:76-121`).

The wrapper contract being witnessed is concrete and inspectable. `scripts/judge.sh` enforces usage/missing-FR errors, the `JUDGE_EXECUTION` recursion sentinel, atomic lock/stale-lock exits, executor resolution, and artifact verification by `tmp/draft-judgement.md` with a verdict line (`scripts/judge.sh:16-22`, `scripts/judge.sh:26-39`, `scripts/judge.sh:43-60`). `scripts/review.sh` mirrors the same shape for `REVIEW_EXECUTION` and requires `tmp/draft-review.md` to put `**Merge verdict:**` on line one (`scripts/review.sh:18-24`, `scripts/review.sh:28-41`, `scripts/review.sh:45-62`). The adapters also preserve the intended advisory/non-authoritative boundary (`.github/skills/judge-fr/adapters/graph.yaml:1-5`, `.github/skills/review-pr/adapters/graph.yaml:1-4`).

The strategic classification is a framework/process primitive: no new runtime abstraction is being added, but the sole judge/review route is a repository-wide authority boundary used by every later FR and PR. The change is therefore justified as local traceability and witness coverage, not feature growth.

## Required revisions

### R-1: Add `ARCHITECTURE.md` to the FR deliverables and acceptance criteria

Fold `ARCHITECTURE.md` into the Proposed Solution, Scope, and Acceptance Criteria. The FR currently requires `capabilities/CAP-211-sole-route-judge-review.yaml` and `python scripts/req_coverage.py --strict` (`feature-requests/FR-758-judge-review-traceability-reconstruction.md:100-107`) but does not authorize the architecture traceability row/section that strict mode requires. `scripts/req_coverage.py` loads requirements from capability YAML (`scripts/req_coverage.py:34-75`), then separately fails `--strict` when any capability requirement is missing from `ARCHITECTURE.md` (`scripts/req_coverage.py:512-525`). Repo doctrine also says tests link to requirements in `ARCHITECTURE.md` and new capabilities use CAP YAML plus REQ markers (`.github/copilot-instructions.md:171-174`).

Mechanically add a required `ARCHITECTURE.md` update: a top capability summary row after CAP-210 and a generated CAP-211 section with a `REQ-YG-569` row, matching the existing shape shown by CAP-210 (`ARCHITECTURE.md:520-528`, `ARCHITECTURE.md:2605-2615`). The CAP YAML should follow the current registry pattern, including `name`, `id`, `status`, `fr`, `feature_request`, `description`, `modules`, and `requirements` as exemplified by `capabilities/CAP-210-edge-shape-classification.yaml:1-34`.

### R-2: Specify the real-smoke evidence contract exactly

Replace the vague "one real smoke execution" acceptance item with exact evidence fields. For each wrapper, the FR must require: command run, timestamp, executor identity (`YAMLGRAPH_BIN`, PATH `yamlgraph`, or `uv run yamlgraph`), exit code, artifact path, and the first artifact lines proving the wrapper contract (`**Verdict:**` for judge; `**Merge verdict:**` on line one for review). The review smoke must also state the PR number or branch input, because `scripts/review.sh` requires both a PR/branch and an FR path (`scripts/review.sh:18-19`); a "trivial FR fixture" alone is not a runnable review smoke (`feature-requests/FR-758-judge-review-traceability-reconstruction.md:86-87`).

The smoke remains manual evidence recorded in the FR, not an automated test or CI requirement. Automated tests must keep using the stub executor described in scope item 3 (`feature-requests/FR-758-judge-review-traceability-reconstruction.md:74-85`).

### R-3: Add an enforcement-infrastructure human-review gate

Add a GATE condition to the FR: any implementation that modifies `scripts/judge.sh`, `scripts/review.sh`, `.github/skills/judge-fr/`, `.github/skills/review-pr/`, CI, hooks, or doctrine/templates must be explicitly human-reviewed before merge. Judge doctrine requires adversarial treatment for enforcement-infrastructure changes (`.github/skills/judge-fr/doctrine.md:94-103`), and review doctrine says the same for CI, hooks, and judge/review doctrine (`.github/skills/review-pr/doctrine.md:71-79`). The current FR mostly authorizes tests/traceability, but it also permits wrapper behavior changes if a porting defect is found (`feature-requests/FR-758-judge-review-traceability-reconstruction.md:108-110`); that exception needs the gate.
