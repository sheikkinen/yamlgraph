# Feature Request: Watcher2 Remediation Loop Crash Fix for Ruff SIM117 Errors

**Priority:** HIGH
**Type:** Bug
**Status:** Proposed
**Effort:** 1 day
**Requested:** 2026-04-25

## Summary

Fix watcher2 remediation loop crashes when encountering ruff SIM117 (nested with statements) errors by enabling unsafe fixes and improving copilot fix context.

## Value Statement

Watcher2 pipeline operators get resilient automated fixing of common ruff linting issues, preventing pipeline crashes that require manual intervention and reducing time-to-merge from hours (manual fix) to minutes (automatic remediation).

## Problem

The watcher2 remediation loop crashes when encountering ruff SIM117 (nested with statements) errors in test files generated by copilot nodes. This failure cascades through multiple remediation attempts and ultimately requires manual intervention.

**Root causes identified:**
1. `ruff check --fix` doesn't auto-fix SIM117 violations (requires `--unsafe-fixes`)
2. Copilot fix step receives generic error context without specific ruff rule information
3. Changelog fragment naming relies on filename extraction, and copilot nodes sometimes use wrong FR numbers
4. 5-attempt remediation loop fails entirely instead of partially succeeding

**Evidence from PR #220 (FR-219):**
- watcher2 got 9 SIM117 errors in `test_prompt_caching_fr276.py`
- Retried 5 times with `ruff check --fix` (no effect on SIM117)
- Invoked copilot fix which also failed to resolve
- Pipeline crashed with exit code 1
- Changelog fragment named `fr-276-prompt-caching.md` instead of `fr-219-prompt-caching.md`

## Proposed Solution

### 1. Enhanced Ruff Command Strategy

Update watcher2.sh finalize section (line ~314) to use progressive fixing:

```bash
# Progressive ruff fixing: safe first, unsafe for remaining issues
git add -A 2>/dev/null || true
ruff check --fix yamlgraph/ tests/ 2>/dev/null || true
ruff check --fix --unsafe-fixes yamlgraph/ tests/ 2>/dev/null || true
ruff format yamlgraph/ tests/ 2>/dev/null || true
git add -A 2>/dev/null || true
```

And CI remediation section (line ~384):

```bash
git add -A && ruff check --fix . && ruff check --fix --unsafe-fixes . && ruff format .
```

### 2. Enhanced Copilot Fix Context

Modify `enforce-ci-remediate.yaml` prompt to include specific ruff error codes:

```yaml
# Extract specific ruff error codes from CI logs
# Example: "SIM117 Use a single `with` statement with multiple contexts"
# Provide specific guidance for common auto-fixable rules
```

### 3. Changelog Fragment Validation

Add validation step before pushing to verify changelog fragment FR number matches worktree branch:

```bash
# In watcher2.sh after finalize step
if [[ -f "changelog/unreleased/"*.md ]]; then
    FRAGMENT_FR=$(grep -oE 'FR-[0-9]+' changelog/unreleased/*.md | head -1)
    BRANCH_FR=$(echo "$WT_BRANCH" | grep -oE 'FR-[0-9]+' | head -1)
    if [[ "$FRAGMENT_FR" != "$BRANCH_FR" ]]; then
        log_warn "Fragment FR mismatch: $FRAGMENT_FR vs $BRANCH_FR"
        # Auto-correct or invoke copilot fix
    fi
fi
```

## Acceptance Criteria

- [ ] `ruff check --fix --unsafe-fixes` runs in both finalize and CI remediation steps
- [ ] SIM117 violations are auto-fixed without manual intervention
- [ ] Copilot fix prompt includes specific ruff error codes and rule names
- [ ] Changelog fragment FR numbers are validated against branch names
- [ ] Remediation loop handles partial success (some fixes work, others need copilot)
- [ ] Tests added covering SIM117 remediation scenarios
- [ ] Documentation updated in watcher2 comments

## Alternatives Considered

1. **Disable SIM117 rule entirely** - Rejected: Rule provides valuable simplification
2. **Manual intervention workflow** - Rejected: Defeats automation purpose
3. **Separate unsafe-fixes step** - Chosen: Progressive approach is safer
4. **Pre-commit hook modification** - Rejected: Problem is in generated code, not authored code
