## What is sound

The FR now satisfies the prior judgement's blocking process defects. It adds a `**Research:**` field that points at `FR-933.research.md`, records that the normal route was waived because `scripts/research.sh` is the component under repair, and cites the earlier C-6 waiver condition (`feature-requests/FR-933-retry-cannot-recover-deterministic-rejection.md:9-16`; `feature-requests/FR-933.research.md:8-24`). The research record is honest about not being persona output, but it still provides a committed alternatives table with seven candidates, a clear `is_this_a_graph`: no answer, and prior-art disposition (`feature-requests/FR-933.research.md:26-55`). That is enough for this special case because the previous judgement allowed a recorded human waiver before rejudgement (`feature-requests/FR-933-retry-cannot-recover-deterministic-rejection.judgement.md:77-84`) and FR-927 provides repo precedent for an operator-recorded waiver plus inline alternatives (`feature-requests/FR-927-retire-fr902-lane-guard-hooks.md:5-7`).

The defect is concrete and bounded. FR-933 names the first consumer as `scripts/research.sh`, says it is failing every run, and records five over-length validation failures across two briefs and four persona/field combinations (`feature-requests/FR-933-retry-cannot-recover-deterministic-rejection.md:19-24`, `feature-requests/FR-933-retry-cannot-recover-deterministic-rejection.md:43-63`). CAP-248 claims an active research sole route with `max_length=400` rejection, preserved disagreement, provenance, and recorded error surfacing (`capabilities/CAP-248-research-sole-route.yaml:1-16`, `capabilities/CAP-248-research-sole-route.yaml:20-51`), so the broken first consumer matters to an active capability claim, not a speculative future path.

The root-cause evidence matches the code. The committed research graph runs at `temperature: 0.0` and all five structured persona nodes use `on_error: retry` with `max_retries: 2` (`examples/demos/research-route/graph.yaml:11-14`, `examples/demos/research-route/graph.yaml:86-91`, `examples/demos/research-route/graph.yaml:99-104`, `examples/demos/research-route/graph.yaml:112-117`, `examples/demos/research-route/graph.yaml:126-131`, `examples/demos/research-route/graph.yaml:169-174`). Node-level retry delegates to `handle_retry` through `lambda: attempt_execute(cfg.provider)`, so it carries no previous-error context (`yamlgraph/node_factory/llm_execution.py:125-131`); `handle_retry` itself accepts a zero-argument callable and only stores the last exception after each identical call (`yamlgraph/error_handlers.py:108-136`). The LLM node resolves variables once before defining `attempt_execute`, which supports the FR's claim that feedback cannot simply appear through existing variable resolution (`yamlgraph/node_factory/llm_nodes.py:323-350`).

The proposal is architecturally aligned and not a disguised resurrection of FR-408. FR-408 proposed a broad runtime repair framework: diagnostic codes, a new `on_error: auto_repair` strategy, repair dispatch, coercion, default injection, and threshold relaxation (`feature-requests/FR-408-runtime-repair-metadata.md:35-124`), and was rejected as disproportionate and partly harmful (`feature-requests/FR-408-runtime-repair-metadata.md:142-146`). FR-933 explicitly forbids those mechanisms and limits itself to reporting the violated constraint back to the model without framework-authored replacement values (`feature-requests/FR-933-retry-cannot-recover-deterministic-rejection.md:129-138`, `feature-requests/FR-933-retry-cannot-recover-deterministic-rejection.md:197-204`; `feature-requests/FR-933.research.md:48-54`). That conforms to the repo doctrine's boundary rule and `two_strike_split`: repeated prompt failures belong in code at the boundary, not in another prompt patch (`.github/copilot-instructions.md:51-53`, `.github/copilot-instructions.md:116-117`).

The scope is single-responsibility and testable. The FR freezes one mechanism - bounded validation feedback on node-level structured-output retry - while preserving all other exception classes and explicitly excluding graph/prompt edits, schema weakening, truncation, new error modes, and invocation-route changes (`feature-requests/FR-933-retry-cannot-recover-deterministic-rejection.md:96-115`, `feature-requests/FR-933-retry-cannot-recover-deterministic-rejection.md:197-204`). Its acceptance criteria are mechanical: RED/GREEN unit tests assert recorded retry inputs, absence of rejected value leakage, success and exhaustion paths, non-validation retry preservation, provider retry preservation, a live `scripts/research.sh` witness, requirement tags, changelog, FR status update, and diary (`feature-requests/FR-933-retry-cannot-recover-deterministic-rejection.md:149-195`). Existing tests already cover node retry counts and executor non-retry behavior (`tests/unit/test_reliability.py:157-200`; `tests/unit/test_executor_retry.py:184-221`), and executor-level provider retry classification is a separate existing policy (`yamlgraph/executor_base.py:60-80`; `yamlgraph/executor.py:140-175`).

Strategic classification: Framework primitive. The immediate witness is the research route, but the failing seam is generic LLM-node structured-output retry. No existing abstraction fits because the executor-level retry only classifies provider/transient exceptions and raises non-retryable validation errors to the node layer (`yamlgraph/executor_base.py:60-80`; `yamlgraph/executor.py:140-165`), while the node layer retries without failure context (`yamlgraph/error_handlers.py:108-136`).

## Revised acceptance criteria

- [ ] AC-01: RED - a unit test builds an LLM node with structured output, `on_error: retry`, `max_retries: 2`, and a stubbed `execute_prompt` that raises a Pydantic `ValidationError` while recording the complete LLM-call input surface used by the implementation. Before the fix, the initial attempt and retry attempt inputs are byte-identical.
- [ ] AC-02: GREEN - the same test proves the first retry after a structured-output `ValidationError` receives bounded validation feedback containing the failing field path, the sanitized validation message, and limit/actual-length metadata when Pydantic exposes it.
- [ ] AC-03: The retry feedback does not contain the rejected field value, whole or truncated. The test uses a distinctive substring from the rejected over-length value and asserts that substring is absent from the retry input.
- [ ] AC-04: A success-path unit test fails validation once, succeeds on the second attempt after receiving feedback, and returns the parsed result under the configured node `state_key`.
- [ ] AC-05: An exhaustion unit test makes every attempt fail validation and proves the node returns a `PipelineError` preserving node name, exception type, and sanitized validation message, with no truncated value, coerced value, or success-shaped state update.
- [ ] AC-06: A non-validation node-level retry test proves retries for a non-`ValidationError` receive the same input as the first attempt and keep existing retry count/error behavior; the existing witnesses in `tests/unit/test_reliability.py:157-200` pass without weakening their assertions.
- [ ] AC-07: Executor-level provider classification remains behaviorally unchanged: retryable provider faults still retry under `yamlgraph/executor.py` policy, and non-retryable exceptions still raise immediately under the existing `tests/unit/test_executor_retry.py:184-221` witnesses.
- [ ] AC-08: Feedback construction uses structured Pydantic error data where available (`loc`, `msg`, `type`, `ctx`) rather than raw `str(ValidationError)` if that raw string would leak `input_value`; no rejected model value is copied into the retry instruction.
- [ ] AC-09: No persona prompt, no `examples/demos/research-route/graph.yaml`, no `max_length=400`, and no rejection-never-truncation contract is changed. If enforcement discovers a governed graph or prompt artifact must change, it stops and returns to planning/rejudgement; any later graph/prompt change must be produced by `scripts/author.sh` with `tmp/draft-authoring-report.md` recording lint, smoke, and limitations.
- [ ] AC-10: `scripts/research.sh feature-requests/research-briefs/fr-938-prior-art-precedent-brief.md` exits 0, writes a non-empty `tmp/draft-alternatives.md` containing five persona rows, and `python scripts/research_preflight.py tmp/draft-alternatives.md` reports zero violations.
