## What is sound

The problem is real and evidenced by the current contract. The FR identifies the accepted route bypass as: skill loaded, doctrine read, precedent searched, then direct in-session authoring (`feature-requests/FR-767-graph-authoring-sole-route.md:16-25`). Current graph-authoring surfaces make that bypass textually defensible: `SKILL.md` first instructs the agent to read doctrine and author through the workflow (`.github/skills/graph-authoring/SKILL.md:23-29`), then scopes `scripts/author.sh` to "delegated authoring" (`.github/skills/graph-authoring/SKILL.md:31-39`); doctrine likewise limits the adapter to "substantial graph creation" and explicitly says repeated local drafting stays in the skill (`.github/skills/graph-authoring/doctrine.md:86-116`). The FR's scope is therefore not speculative prose polish; it closes an observed ambiguity in the governing route.

The parity target is valid. Judge-fr already uses a single route, explicitly labels the adapter as `(SOLE ROUTE)`, names forbidden alternatives, and carries the "fix the toolchain, do not route around it" rationale (`.github/skills/judge-fr/SKILL.md:31-51`). FR-765's second-round judgement approved a thin authoring adapter and `scripts/author.sh` wrapper as an execution route over existing copilot-node capability (`feature-requests/FR-765-graph-authoring-workflow-skill.judgement.md:95-105`), while the delivered adapter already has the load-bearing `allow_all_paths` and `allow_all_tools` flags (`.github/skills/graph-authoring/adapters/graph.yaml:18-32`) and the wrapper verifies the report artifact instead of trusting exit code (`scripts/author.sh:55-78`). Reusing that route is architecture alignment, not invention.

The strategic classification is enforcement/doctrine hardening for an existing workflow-skill route, not a framework primitive. The FR has one concern: make graph-authoring route compliance impossible to bypass defensibly. The doctrine and wrapper changes (D-1..D-3) explain the rule, and the hook/backstop (D-4) enforces it (`feature-requests/FR-767-graph-authoring-sole-route.md:84-144`). Repo doctrine supports moving repeated instruction failures into code: `two_strike_split` says repeated failures in the same class belong at a code boundary, and `detection_without_enforcement` says lint without a gate is advisory (`.github/copilot-instructions.md:116-117`, `.github/copilot-instructions.md:147-158`).

The proposed hook surface is feasible, but only after the revisions below. PreToolUse hooks already run before tools and can deny with `permissionDecision: "deny"` (`.github/hooks/README.md:38-66`); the active `pre-command-guard` is wired as a PreToolUse hook (`.github/hooks/pre-command-guard.json:1-11`) and currently inspects terminal commands (`.github/hooks/scripts/pre-command-guard.sh:156-160`). Existing hook helpers also already know how to parse edit-tool file paths, including `apply_patch` `Add File` and `Update File` headers (`.github/hooks/scripts/checks/common.sh:10-56`). Tests for pre-command guard payloads, audit entries, lockdown, and terminal denial already provide the right harness to extend (`.github/hooks/tests/test_pre_command_guard.py:23-49`, `.github/hooks/tests/test_pre_command_guard.py:366-420`).

The prior art is dispositioned. FR-765 created the route but left "delegated"/"substantial" language that this FR identifies as the root defect (`feature-requests/FR-765-graph-authoring-workflow-skill.md:227-269`, `.github/skills/graph-authoring/doctrine.md:86-116`). FR-737 supports hook retrieval plus judge disposition rather than relying on memory (`feature-requests/FR-737-graveyard-hook-prior-art-on-fr-creation.md:20-42`). FR-763 supports boundary normalization against workspace pollution (`feature-requests/FR-763-taxonomy-scan-git-tracked-boundary.md:44-67`). The 2026-07-29 diary records strike 1, where a file-move framing bypassed the authoring skill and only habit caught a provider misconfiguration (`docs/diary/diary-2026-07-29-skill-trigger-artifact-class.md:5-27`).

## Required revisions

### R-1: Define the authoring sentinel as a scoped, non-global allow token

Replace the current sentinel description with a mechanical predicate the hook can test without guessing. `scripts/author.sh` currently exports only `AUTHOR_EXECUTION=1` for the child route and holds a local lock (`scripts/author.sh:20-40`, `scripts/author.sh:55-57`); FR-767 asks for a tmp sentinel carrying adapter session identity, but does not define how the PreToolUse hook distinguishes the adapter's child agent from another simultaneous session (`feature-requests/FR-767-graph-authoring-sole-route.md:132-134`).

Fold into the FR: `scripts/author.sh` must create a per-run sentinel containing an unpredictable token and route metadata, pass that token to the adapter execution environment, and remove the sentinel on wrapper exit. The PreToolUse guard may allow governed writes only when the environment token matches the sentinel and the sentinel is fresh. A plain global file such as `tmp/.authoring-sentinel` that allows all sessions while present is forbidden. The FR may additionally bind to `session_id` if the child session id is available in the hook payload, but it must not require an identity the wrapper cannot know before launching the copilot node.

### R-2: Replace "material edits" and warn-only carveouts with a bright-line rule

D-4 currently says the guard denies new-file creation plus material edits, but warns for repairs to existing committed graphs (`feature-requests/FR-767-graph-authoring-sole-route.md:135-139`). That contradicts D-1's claim that the adapter is the sole route for all governed authoring (`feature-requests/FR-767-graph-authoring-sole-route.md:88-98`) and is not mechanically testable before the edit runs: a PreToolUse hook sees the target path and command, not a reliable semantic classification of whether a node/edge/prompt change is "material" (`.github/hooks/README.md:48-66`).

Fold into the FR: for agent sessions, any unsentineled write to a governed artifact path is denied, whether the path is new or tracked. Governed artifact paths are exactly `examples/**/graph.yaml`, `examples/**/prompts/*.yaml`, `graphs/*.yaml`, `.chaplain/graphs/*.yaml`, and any additional prompt paths explicitly listed by the revised FR. If the project needs a non-authoring maintenance escape hatch, it must be a separate, explicit operator command or separate FR; it must not be an implicit "warn-only materiality" judgement inside the hook.

### R-3: Specify all write surfaces and command shapes the guard must parse

The FR correctly says the 2026-07-29 bypass used the terminal surface and that file-write tools must also be covered (`feature-requests/FR-767-graph-authoring-sole-route.md:121-131`), but the acceptance criteria are not yet precise enough to implement. The active pre-command guard currently passes non-terminal tools without inspection (`.github/hooks/scripts/pre-command-guard.sh:156-160`), while shared post-edit parsing already recognizes `replace_string_in_file`, `create_file`, `multi_replace_string_in_file`, and `apply_patch` (`.github/hooks/scripts/checks/common.sh:10-56`). The revised FR must name the exact surfaces and tests so enforcement is not a regex costume.

Fold into the FR: PreToolUse coverage must include `create_file`, `replace_string_in_file`, `multi_replace_string_in_file`, and `apply_patch` paths; terminal commands using `cp`, `mv`, `tee`, heredocs, or `>`/`>>` redirection to governed paths; and at least one quoted-path variant. The tests must prove deny without sentinel and allow with sentinel for each supported surface. If a terminal command shape cannot be parsed safely, the guard must deny with a route-to-`scripts/author.sh` message rather than silently approve. Do not rely on PostToolUse for prevention; PostToolUse may only provide advisory diagnostics after the PreToolUse gate exists.

### R-4: Make the commit/merge backstop possible in a clean checkout

D-4 says the all-routes backstop is a commit-boundary check that a commit introducing a new governed `graph.yaml` includes the authoring-report artifact (`feature-requests/FR-767-graph-authoring-sole-route.md:139-143`). The current report path is `tmp/draft-authoring-report.md` (`.github/skills/graph-authoring/doctrine.md:64-69`, `scripts/author.sh:11-12`), and `tmp/` is ignored (`.gitignore:21-25`). A CI merge gate cannot see a local ignored `tmp/` proof in a clean checkout; a pre-commit hook can read it locally, but that is not the same as a PR merge backstop.

Fold into the FR by choosing one explicit model: either (a) local-only pre-commit proof, where a staged new governed artifact must be listed in the current `tmp/draft-authoring-report.md`, with no CI/merge-boundary claim; or (b) tracked proof, where the authoring route writes or copies a reviewable report/proof into a committed path and CI verifies it. If the FR keeps the `enforcement_at_merge_boundary` claim, it must choose model (b), name the tracked artifact path and required headings, and update `.gitignore`/CI scope accordingly. Do not leave the enforcer to invent this at implementation time.
